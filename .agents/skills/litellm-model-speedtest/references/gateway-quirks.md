# 360 LiteLLM 网关特性与排障归因

本文件供排查网关连接失败或特定模型测速异常时查阅。

## 关键事实

- **域名网络代理**：360 网关域名必须走本地代理解析（默认 `http://127.0.0.1:7897`，与 Pi settings 的 `httpProxy` 一致），直连会导致 `Could not resolve host`。
- **协议格式**：对话端点为 Anthropic Messages 格式（`POST /v1/messages`，需携带 `x-api-key` 与 `anthropic-version: 2023-06-01`）。
- **凭证读取**：API key 优先从仓库根目录 `.env` 的 `LLM_API_KEY` 读取，可通过 `--api-key` 显式传入覆盖。
- **模型端点差异**：
  - `/v1/models` 返回可路由的模型 ID 全集（以本列表为测速准绳）；
  - `/model/info` 返回部署元信息（同模型名可能包含多条部署记录，只取第一条）。
- **非对话模型**：`/v1/models` 中包含 embedding（如 `bge-m3`）、图像生成（如 `qwen-image`）、plan 类及路由组，测速返回空或失败属正常现象。

## 常见失败归因

| 状态/现象 | 原因 | 处理方案 |
|:---|:---|:---|
| 403 Forbidden | 当前 key 无该模型权限 | 更换 API Key 或申请权限 |
| 404 / 503 | 网关未配置可用后端 Channel | 属于网关侧配置缺失，由管理员排查 |
| ReadTimeout | 慢推理模型冷启动或长思考 | 慢模型需加大 `--timeout 120` 或更高，非服务崩溃 |
| TTFT 为 `(无正文)` | 预算内仅输出思考或属于非对话模型 | 属于推理模型正常现象或非对话模型 |

## 节点速度差异

同模型不同部署节点（如 `m1/`、`360/`、`-openai`、`m2/`）速度可能相差数倍，在配置或调用时务必核准前缀。
