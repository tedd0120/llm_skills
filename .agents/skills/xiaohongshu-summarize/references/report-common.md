# 报告共享规范

所有报告必须遵守本文件；再叠加一本任务形态 runbook。

## 1. 搜索概览

将「搜索概览」作为报告第一个二级板块：

```markdown
## 搜索概览

| 搜索任务 | <主旨> |
|:--|:--|
| 执行时间 | <YYYY-MM-DD HH:MM> |
| 数据规模 | <U> 组独立内容（原始 <S> 条，去重 <D>）· 实际分析 <C> 条评论（覆盖 <P> 组，来源页面累计 <T> 条） |
```

- 从 `dedup.posts_scraped/posts_unique/dropped_duplicate` 读取 S/U/D；旧数据无 `dedup` 时，令 S=U=`posts` 长度、D=0，并标注「旧数据未提供去重统计」。
- `dedup.dropped_id_mismatch > 0` 时，在数据规模行末追加「ID 不匹配丢弃 <N> 条」。
- C 为所有帖子实际保存的评论条数之和；P 为实际保存至少一条评论的独立内容组数；T 为所有 `comments_count` 之和。
- `comments_captured` 仅用于交叉核对，最终以 `comments` 实际长度为准。
- 固定模式在概览内追加 `关键词 | 篇数 | 搜索意图` 表。
- 发散模式在概览后追加「搜索发散路径」，列为 `轮次 | 关键词 | 实际篇数 | 发散理由`。

## 2. 证据等级

所有结论按去重后的独立内容组数分级：

| 等级 | 独立内容组数 | 允许的结论强度 |
|:--|--:|:--|
| 充分 | ≥10 | 可支持首选或高置信结论 |
| 中等 | 5–9 | 可作备选或中等置信结论，必须标注 |
| 不足 | <5 | 只能列为「候选但证据不足」，不得进入首选或备选 |

- 总样本少于 50 组时，在报告醒目位置标注「样本有限」，并将所有证据等级降一档。
- 证据数只按独立内容组计数；同一帖子中的多条评论不得重复抬高等级。
- 点赞数不得代替证据组数。仅当评论为结构化对象且 `likes` 可用时，才可称某条评论为「高赞评论」；否则使用「多组内容提到」等可复核措辞。

## 3. 引用与可追溯性

引用格式由 `hyperlinks` 决定：

| 内容类型 | 超链接关闭 | 超链接启用 |
|:--|:--|:--|
| 帖子标题 | `*《标题》*` | `[*《标题》*](id:{post_id})` |
| 用户评论 | `_"评论内容"_` | 同左 |
| 来源标注 | `来源：*《标题》*` | `来源：[*《标题》*](id:{post_id})` |
| 追溯来源 | `追溯来源：*《标题》*` | `追溯来源：[*《标题》*](id:{post_id})` |

- 帖子缺少 `post_id` 时降级为纯文本，禁止生成 ID 占位符。
- 每项关键结论都附帖子标题、作者、日期与能支撑结论的关键引用。
- 进入首选或备选的每个候选实体至少附 1 条来源引用。
- 不在报告中披露评论者昵称；评论作者仅用于采集质量核对。

## 4. 分析纪律

- 用 LLM 完成实体识别、观点归纳、情感判断和冲突裁决；禁止用脚本或正则做内容分析。
- 允许脚本或计算工具统计帖子、评论、证据组数及数值字段。
- 明确区分事实、用户体验、推断和未知；冲突证据不得并列后不作裁决。
- 软广只能标为「疑似」并说明可观察信号，不得仅凭怀疑删除证据。
