# 推荐/选购报告 Runbook

回答「我最后该选哪一个」。适用于商品、服务、内容和目的地推荐。

## 1. 候选实体映射

始终比较可直接采取行动的候选实体，不要停在上位分类：

| 主题 | 候选实体 | 声量维度 | 成本维度 | 排除维度 |
|:--|:--|:--|:--|:--|
| 实物商品 | 具体型号 | 品牌 | 常价/好价 | 避雷型号 |
| 本地服务 | 具体店铺 | 商圈/菜系 | 人均 | 踩雷店 |
| 内容消费 | 具体作品 | 制作方/题材 | 可省略 | 弃看雷点 |
| 目的地 | 具体目的地/线路 | 国家/区域 | 预算 | 不推荐时段 |

## 2. 必须输出的结构

在搜索概览（及可选的搜索发散路径）后，立即输出：

```markdown
## 选购结论

**一句话**：<主要人群/场景> → 选 <首选实体>，<具体成本或门槛>；<最常见例外条件> 则改选 <备选实体>。

| 定位 | 候选实体 | 成本 | 选它因为 | 什么情况别选它 | 证据 | 内容质量提示（可选） |
|:--|:--|:--|:--|:--|:--|:--|
| 首选 | ... | ... | ... | ... | 充分（N 组） | ... |
| 备选 | ... | ... | ... | ... | 中等（N 组） | ... |
| 低成本位 | ... | ... | ... | ... | 中等（N 组） | ... |
| 不建议 | ... | — | — | ... | 充分（N 组，负面集中） | ... |

**改选规则**：<条件 A> → <实体 X>；<条件 B> → <实体 Y>。

### 首选的已知短板与裁决

| 反对意见 | 是否属实 | 对本次主题是否致命 |
|:--|:--|:--|
| ... | 属实/存疑 | 致命/不致命/不适用（反馈来自 <其他人群>） |
```

随后依次输出：

1. `## 场景化选择`：每个场景最多一个首选和一个备选，并写明不适用条件。
2. `## 关键证据与共识`：按候选实体组织支持与反对证据，处理冲突。
3. `## 排除项与剩余集合`：说明排除原因，结尾列出与置顶短名单一致的剩余集合。
4. `## 附录：声量与热度`：仅在数据支持时输出。
5. 按 common 输出 `## 数据来源说明`。

## 3. 硬约束

- R-1 结论前置：`选购结论` 必须是搜索概览和可选发散路径后的第一个决策板块。
- R-2 单一首选：短名单中「首选」有且只有一行。
- R-3 证据门槛：「不足」实体不得进入首选、备选或低成本位，只能列入「候选但证据不足」。
- R-4 允许无结论：无实体达到「充分」时，将首选写为「暂无——现有样本不足以选出第一名」，并列出能补足证据的搜索词；不得抬高弱候选。
- R-5 实体粒度：矩阵列头使用候选实体而非品牌、商圈、制作方等上位分类；成本使用具体常价，不给跨数倍的品牌区间。
- R-6 场景收敛：每个场景最多一个首选和一个备选；禁止「上位分类 + 一串实体」。
- R-7 冲突裁决：逐条判断首选短板是否属实、是否对当前人群致命；写「不适用」时说明反馈来自哪个不同人群。
- R-8 声量降级：将声量放到末尾附录，声明口径和分母；多选提及率不得凑成 100%，并写明「高声量可能反映投放强度，不等于更值得选」。
- R-9 排除呼应：排除项末尾给出剩余可选集合，并与置顶短名单一致。
- R-10 成本合并：将成本并入短名单；仅在确有跨候选通用规格常识时另设规格说明。

## 4. 时效与内容质量

- 价格必须附观察时间或来源日期，并标注「价格具有时效性，以购买时页面为准」。
- 仅在出现重复文案、密集同构表述、明确商业披露等信号时填写「内容质量提示」；统一使用「疑似软广」，列出信号，不推断未披露的商业关系。
- 结构化评论的点赞数可帮助挑选代表性引文，但不得改变按独立内容组数计算的证据等级。
