# 迁移执行

## 每个迁移项

1. 前置检查：扫描结果 `active_pids` 为空；`referenced_by` 已逐个读过。有占用时跳过该项，在 `plan.md` 标为“待服务停止”。
2. 记录摘要：移动前对源目录计算清单，写入 `.work/<本任务ID>/evidence/migration-before.txt`：

   ```bash
   (cd <源目录> && find . -type f -print0 | sort -z | xargs -0 sha256sum) > <证据文件>
   ```

3. 移动：同一文件系统用 `mv`（重命名，原子）；跨文件系统先复制、校验摘要一致后再删源。目标父目录不存在时先建。
4. 校验：对目标目录重算清单，与移动前比对，结果写入 `evidence/migration-after.txt`，不一致立即停止并报告。
5. 更新引用：`referenced_by` 中的有效说明与执行入口改到新位置；历史记录、来源快照中的旧路径保留原文，若其措辞把旧位置描述为“当前”“权威”，改为“历史记录”。
6. 空目录：源目录为空或只剩工具自建的 `.gitignore` 时删除。

## 目标命名

- 旧目录名已是 `yyyyMMdd_HHmmss_<主题>`：时间保留，主题转为小写连字符形式，作为任务 ID。
- 旧目录名无时间：取目录内最早文件的修改时间，主题从目录名或内容概括；无法判断时问用户。
- 多个旧目录属于同一任务（同名计划、原型、临时材料）：合并到同一任务 ID 的不同子目录。
- 旧计划文件 `docs/plans/<时间_主题>.md` → `.work/<任务ID>/plan.md`；同一任务的附件目录 → `evidence/`。

## 代码中的硬编码路径

测试或脚本把输出写到旧目录时，改为临时目录或测试框架输出目录（如 Playwright `testInfo.outputPath()`、pytest `tmp_path`、`tempfile`）。改完运行受影响的测试，并确认运行后旧目录不再被创建。

## 工具安装（用户同意时）

把本 skill 的 `scripts/artifacts.py` 复制到目标仓库的工具目录（如 `tools/artifacts.py`），规范文档中的“查看与清理”一节指向该路径；目标仓库有测试约定时同步补测试。未安装时，规范中的清理步骤写为手动命令并保留“先预览、确认任务结束、再删除、再核对”的顺序。
