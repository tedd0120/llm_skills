# 分类与问询

## 五种归属

| 层 | 判据 | 去向 |
|---|---|---|
| `asset` 正式资产 | 需要评审、需要他人复现：源码、测试、文档、ADR、配置模板、锁文件、团队共享的 agent 指引 | 原位，Git 跟踪 |
| `work` 任务工作区 | 为某一次任务产生，任务结束即失去大部分价值：计划、原型、临时脚本、日志、截图、子代理材料 | `.work/<任务ID>/` 对应子目录 |
| `local` 本机持久状态 | 跨任务复用、只属于本机：测试账号、本地数据库、服务与隧道记录、发布包、本地 issue、工具本机配置 | `.local/<用途>/` |
| `program` 程序自管 | 路径由代码或第三方工具决定：依赖、构建产物、缓存、索引、运行时锁、AI 客户端状态 | 原位，Git 忽略，不放任务材料 |
| `secret` 机密 | 凭据、密钥、本机连接参数 | 原位，Git 忽略；只看文件名，不读内容 |

`legacy` 是旧布局的 `work` 材料，按 `migrate_to` 迁移；`ask` 与 `unknown` 必须问用户。

## 判定顺序

对扫描结果的每一条：

1. `layer_guess` 为 `asset`、`program`、`secret`、`work`、`local`（根层级）且无 `questions`：直接采纳。
2. `legacy`：按 `migrate_to` 生成迁移项；按内容推断任务主题与时间，推断不出时进入问询。
3. `ask`、`unknown`、带 `questions` 的条目：进入问询。
4. 自行查看再问：列出目录下前 20 个文件名、最近修改时间、`referenced_by` 中代码如何使用该路径（读引用处上下文）。写入方是代码时，多为 `program`；写入方是人或 agent 时，多为 `work` 或 `local`。

## 问询方式

- 一次问完：把所有待确认条目合成一轮，按“最可能的归属”分组，每条给出证据和推荐选项。
- 每条附：路径、大小、最近修改、跟踪/未忽略文件数、谁在引用、推荐归属与理由。
- 选项固定为：正式资产（跟踪）/ 任务材料（迁入 `.work`）/ 本机状态（迁入 `.local`）/ 程序自管（原位忽略）/ 混合（逐子路径说明）/ 删除。
- 混合目录（如 `configs/` 模板跟踪、实值忽略）按子路径拆分归属，分别写忽略规则。
- 用户的回答写入 `plan.md` 的归属表，标注“用户确认”。

完成标准：扫描结果中每条 `questions` 非空的条目都有用户给出的归属。

## 常见判断

| 现象 | 倾向 |
|---|---|
| 目录只有 `.gitkeep` 被跟踪，其余忽略 | `program` 或 `local` 的占位目录，保留 `.gitkeep` 与 `dir/*` + `!dir/.gitkeep` |
| `*.example.*`、`*.template.*` 被跟踪，同名实值被忽略 | 混合：模板 `asset`、实值 `secret` 或 `local` |
| 已被忽略但代码硬编码写入 | `program`；迁移需改代码，默认不动 |
| 文件名带时间戳、内容是计划或结论 | `work`，迁入对应任务 ID |
| 模块内自带 `.gitignore` 与 `.local/` | 模块自治，默认保留原位，问用户是否并入根 `.local/` |
| 测试把输出写到仓库内固定路径 | 改测试输出到临时目录或测试框架的输出目录 |
| skill、流水线或工具运行得到的报告、导出、抓取结果（如 `data/<skill>/`、`runs/`） | `program` 层的业务产出，原位保留，只统一子目录与命名；不迁入 `.work` |
| skill 登录态、cookie、token 放在 skill 源码目录 | `local`，迁到 `.local/<skill>/`，读取处统一解析 |
