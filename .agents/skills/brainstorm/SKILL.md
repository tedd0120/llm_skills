# 头脑风暴「三脑会审」

把一个模糊的概念，经过拷问 + 三脑独立判断 + 综合评审，磨成一份扎实的方案。全程说人话，不直播方法论口吻（不说"现在进入阶段二"）——用户要的是拷问、方案、最终结果。

## 默认参数（用户可口头覆盖）

- **codex**：模型 `gpt-5.6-sol`，`model_reasoning_effort=medium`
- **claude**：模型 `sonnet`，`--effort medium`

用户点名换哪个就只换哪个，其余保持默认，别每次问。生效值要替换进阶段 2 的命令里。

## 任务档案（全程落盘）

每次新脑暴，在当前目录下建档：

```
.brainstorm/<yyyyMMdd_主题>/    主题取 2~6 字短语（只用中文/字母/数字/下划线），如 20260717_技能市场
├── qa.md            原始概念 + 逐轮拷问 QA + 共识清单
├── plan_main.md     主 agent 方案
├── plan_codex.md    codex 方案
├── plan_claude.md   claude 方案
└── plan_final.md    究极 plan
```

落盘解决两个真问题：拷问轮数多了，早先的原话会被上下文摘要吞掉，写进文件才不会丢；跑完之后用户和后续会话都能直接翻档案，不用翻聊天记录。会话中断后重开，读一遍 qa.md 就能原地续。

qa.md 骨架：

```markdown
# <主题>（yyyy-MM-dd）

## 原始概念
<用户原话>

## 拷问 QA
### Q1 <问题>
- 推荐：<你的推荐答案>
- 答：<用户原话>

## 共识清单
<收尾时写>
```

---

## 阶段 1：拷问（自适应，≤10 轮）

### 开场：先对齐基线
用户给出概念后，**先用一两句人话复述**你理解的概念（不贴标签），让用户确认或修正。这是第 0 步，不计入轮数。**确认后立即建档**：新建任务文件夹和 qa.md，原始概念先落盘。

### 拷问规则（套用 grilling 框架）
- **严格一问一答**：每次只问一个问题，**附你的推荐答案**，等用户反馈后再进下一问。一次抛多个问题会让人懵。
- 用户能采纳推荐就说"采纳"，想改就说改动点——别逼用户每次从头想。
- 能从环境（文件、已有配置）查到的事实，**自己查**，别问用户；**决策**才问用户。
- **每轮拿到回答，当场把该轮 Q（含推荐）+ A 原话追加进 qa.md**；用户推翻之前的口径，就回去改对应条目。别攒到最后一起补——攒着就是在赌记忆。

### 自适应轮数（关键）
先扫这 6 个维度（用户开场已经说清的直接跳过），**起步 5-6 轮**：
1. **目标**：做成什么样算成功？
2. **受众/场景**：给谁用、在什么场景下用？
3. **约束**：时间、技术、资源、不可动的边界？
4. **成功标准**：可检验的"做完了"长什么样？
5. **非目标**：这次明确不做什么？
6. **风险/失败模式**：最容易在哪翻车？

然后按这三条规则收放轮数：
- 用户答得**模糊**或**暴露新分支** → 追问，往深挖，**最多到 10 轮**。
- 用户**连续 2 轮**都是"采纳推荐、无新信息" → 提前结束，别凑数。
- **达成共识** → 立即收手，哪怕才问到第 4 轮。

### 收尾
拷问结束，写一份**共识清单**（2-3 句人话，不列"真实意图/约束"这种标签）进 qa.md，同时回对给用户："共识对齐了，我接下来让 codex 和 claude 各自独立出一份方案，再和我的一起综合——开始吗？"**等用户点头再进阶段 2。**

---

## 阶段 2：三脑独立出方案

### 三脑必须真并发，零时间差
codex、claude、主 agent 三份方案**必须在同一时刻启动、互相看不到对方产出**。任何一脑先看到了另一脑的结果（哪怕一句话摘要），那一脑就废了——这就是污染，独立性是这套流程的存在意义。

落地方式：
1. **同一条消息里一次性发出两个 Agent tool use**（codex 一个、claude 一个），后台并发跑——两个调用必须在这一个 assistant turn 里同时发出，**绝不前后分两次发**，分次就有时间差，先跑完的那脑的结论会渗进你后面写主脑方案时的判断里。
2. 发完两个调用，**同一回合立刻**开始写主 agent 自己的方案（plan_main.md，结构同阶段 3 的五节），不要等任何一个 subagent 返回再动笔——等了就是让主脑被动脑带节奏。
3. **plan_main.md 定稿之前，不看任何 subagent 带回的结果**；同理，主 agent 已经成型的思路、推荐、取舍**绝不回灌**进给 subagent 的 prompt（见下"给 subagent 的输入"）。
4. plan_main.md 永远不下发给任何 subagent；档案夹里其他文件 subagent 也不准碰。

### 给 subagent 的输入：只给客观信息，绝不夹带主 agent 主观判断
两脑拿到的输入**完全相同**。但"相同"还不够——**内容必须是纯客观的**，否则你把私货塞给两脑，三脑会审就退化成一言堂：

- ✅ **可以给**：qa.md 里的**客观内容**（原始概念原文、用户每一轮的回答原话、共识清单里的事实与约束）+ 用户提供的**任何客观资料**（文件路径、配置、数据、链接、代码片段等）。
- ❌ **禁止夹带**：主 agent 在拷问阶段给的**推荐答案**、任何倾向性措辞（"我倾向于 / 建议 / 应该 / 最好是 / 个人觉得…"）、对答案的暗示、主 agent 自己的思路或方案草稿。

操作上：qa.md 里每轮 Q 都附了一行"推荐：<你的推荐答案>"，那是拷问时方便用户决策用的，**属于主 agent 主观判断**。构造给 CLI 的 prompt 文件时，**必须把所有"推荐："行剔除**，只保留客观的问题本身和用户的回答原话；共识清单也只摘取客观事实与约束，不抄主 agent 的取舍倾向。用户额外提供的客观资料原样附进 prompt。

### subagent 指令（两脑共用，只有跑的命令和产出文件名不同）

**主 agent 先构造客观 prompt 文件，再派两脑**：在发两个 Agent 调用的**前一步**，先把给 CLI 的 prompt 写成一个临时文件（如 `.brainstorm/<主题>/_prompt.txt`）。这个文件里只能装客观信息——步骤见上一节"给 subagent 的输入"。写完后立刻在同一条消息里并发派发 codex 和 claude，中间不留任何能让主脑思路渗回去的窗口。

```
任务：调用 <codex|claude> CLI，让它根据输入独立产出一份方案，存盘后回报。
你只是搬运工：不要总结、不要评价、不要润色、不要掺入自己的看法。

【输入】只有一个文件：<_prompt.txt 的绝对路径>
只准读它。同文件夹里的其他文件一律不许读——qa.md 里有主 agent 的推荐，
plan_main.md 是别人的答卷，看了任一个都作废。

【执行步骤】
1. 读 _prompt.txt，把它整个作为 prompt 喂给 CLI（内容里有引号、反引号、$ 都很正常，
   塞进命令行双引号里必炸，走文件 + stdin）。
2. 用 Bash 跑对应命令（见下），timeout 设 600000——CLI 推理常要几分钟，默认 2 分钟会被掐死。
3. 把方案正文（去掉横幅、统计等非正文）写入 <plan_codex.md|plan_claude.md 的绝对路径>，
   然后简短回报：成功与否 + 文件路径 + 一句话概括。不用把全文贴回来。

【注意】CLI 报错或超时：不要写方案文件，如实回报错误信息和你的诊断，不要伪造方案。
```

> **为什么从"直接读 qa.md"改成"主 agent 先搓一个客观 prompt 文件"**：qa.md 里每轮都挂着主 agent 的"推荐："答案，那是主观判断，直接让两脑看到就等于把答案喂过去了，三脑会审失真。主 agent 在搓 prompt 文件时必须亲手把所有推荐行、倾向性措辞剔除，只留客观问题、用户原话、共识事实与用户提供的客观资料。这是把"客观输入"这条红线落到一个可操作的步骤上。

两脑的命令（默认参数处替换成本次生效值）：

- **codex**：`codex exec --skip-git-repo-check -m gpt-5.6-sol -c model_reasoning_effort=medium - < prompt.txt`
  （输出去掉启动横幅 workdir/model/approval 几行和 token 统计行）
- **claude**：`claude -p --model sonnet --effort medium < prompt.txt`
  （`-p` 直接输出正文，无需解析）

### 降级处理（subagent 或 CLI 失败时）
- 某脑报错 / CLI 不可用 / 返回乱码 → **明确告诉用户"X 脑离线"**（说清是 codex 还是 claude，附错误摘要），不静默吞错。
- 用剩余可用的方案继续阶段 3。哪怕只剩主 agent 一份，也照走综合流程，但要在最终 plan 里说明"本次仅单脑意见，多样性不足"。
- 两脑都挂 → 别硬凑究极 plan，把主 agent 方案 + 失败原因交给用户，让用户决定重试还是就用这一份。

---

## 阶段 3：综合评审 → 究极 plan

读回全部可用方案（plan_codex.md / plan_claude.md + 自己的 plan_main.md），评审综合成**究极 plan**：**写入 plan_final.md，同时在对话里完整给用户看**——文件是留底，不能只丢个路径让用户自己打开。结构：

```markdown
# <方案标题>

## 背景与目标
（从三方共识提炼，2-4 句；有分歧就点出）

## 核心方案
（综合后的最优解。不是简单拼接三份，而是取长补短后的整合答案）

## 关键决策
（逐条列出。三方一致的标 ✅；有分歧的标 ⚠️ 并单独说明：
  - 分歧点是什么
  - 各方分别主张什么
  - 你为什么这样取舍）

## 风险
（三方合并去重。每条标注来源：[主/codex/claude/多方]）

## 下一步行动项
（可执行的 next steps，明确谁做什么）
```

### 评审原则
- **不是投票**，是综合：三方都说 X 不代表 X 对，要给理由；一方独到的洞察要采纳进来。
- **分歧比共识更有价值**：分歧点单独标出来给用户看，让用户自己定夺，别替用户抹平。
- **标清来源**：每个关键观点注明来自哪一脑，方便用户判断可信度。

---

## 全局红线

1. **独立性不可破**，两条硬约束缺一不可：
   - **并发零时差**：codex、claude、主 agent 三份方案必须在同一时刻启动、互相看不到对方产出。两个 Agent 调用必须在**同一条消息里同时发出**，绝不分两次；主脑方案同一回合立刻开写，不等任一 subagent 返回。
   - **输入纯客观**：给两脑的 prompt 只能含 qa.md 里的客观内容（原始概念、用户原话、共识事实与约束）+ 用户提供的客观资料；**所有主 agent 的推荐、倾向、思路一律剔除**（构造 prompt 文件时亲手把"推荐："行和暗示性措辞删干净）。
2. **不直播方法论**：说"我让 codex 和 claude 各自独立看一遍"，不说"现在进入阶段 2"。
3. **不静默吞错**：CLI 挂了、超时、返回异常，都如实告诉用户，降级继续，不假装全跑通。
4. **边聊边落盘**：每轮 QA 当场写进 qa.md，三份方案和究极 plan 都进档案夹；该给用户看的照样在对话里完整给，文件是留底不是替代。
