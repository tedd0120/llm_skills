# 发布、安装与验收契约

## 产物与版本绑定

明确程序版本真源，以及构建配置、Git 标签与更新清单的同步位置。按框架规则比较版本号并定义稳定版、预发布、版本撤回与降级策略：修复线上缺陷优先发布更高版本；确需降级时，单列客户端降级许可、数据向后兼容与验证步骤。

按“平台 / 架构 / 安装格式 / 清单字段 / 签名文件 / 差分资产 / 命名规则”列出发布产物表。更新清单与安装包必须锁定在同一个 Release 下读取，避免并发请求 `latest` 时混用不同版本的清单与资产。

更新签名（由更新器校验发布者密钥）与系统代码签名（Windows Authenticode、macOS Developer ID 及公证）分别配置、独立验收。

## 签名要求与 Windows 分发

根据锁定更新器版本、安装格式、分发渠道及设备策略判断 Authenticode 是否必需。Windows 直接分发的 NSIS 应用可以采用独立更新签名。此时允许安装器不做 Authenticode 签名，发布条件以经过核查的客户端验签实现为准。

- 更新私钥可自行生成并安全保存；客户端内嵌公钥。签名覆盖完整更新包，或覆盖包含安装包名称、版本、目标架构、大小与安全摘要的清单。客户端在解析清单、下载和安装的对应阶段核验信任链。
- 安装前重新核验实际文件，拒绝缺失或错误签名、篡改的清单和安装包、错误版本与架构。仅有 HTTPS 或未签名摘要不能建立发布者密钥信任。
- Windows 代码签名用于系统发布者身份与信任判断。未签名安装器可能受到 SmartScreen、UAC 或设备策略限制，独立更新签名不会消除这些限制。商店、企业策略或现有安装身份要求证书时，保留相应条件。

方案分别写明每种签名的依据与验收结果。用户选择独立更新签名时，将私钥、公钥与发布配置纳入实施范围，不因缺少可选 Windows 证书阻止该发布方式。

## CI 与原子发布顺序

沿用项目既有的包管理器与锁文件，在干净 checkout 中安装依赖。编译期内嵌的前端构建物、静态资源或生成代码必须先于原生宿主编译完成。给具体命令或 workflow 前，先核实目标仓库的 `scripts`、工具链版本、工作目录与认证机制。

标准发布动线：**版本与标签预检 → 静态与测试检查 → 多平台构建与所需签名 → 全量上传至 Draft Release → 远端草稿校验 → 正式公开 Release**。

- **权限与密钥隔离：** workflow 写权限仅授予发布 job，第三方 Action 固定到明确版本或 commit SHA；签名私钥与口令仅注入签名步骤，核查 Vite 等前端构建工具的环境变量前缀过滤规则，确保敏感变量不进入客户端产物。
- **并发与幂等预检：** 预检同名标签与已发布 Release，用并发组（`concurrency`）串行化发布任务，保护已发布的线上资产。
- **远端草稿校验：** 所有平台产物全部上传至草稿后，校验目标架构、版本号、清单引用、远端字节一致性（与同次 CI 构建产物比对）及更新签名。SHA 摘要用于校验字节完整，发布者身份由签名证明。
- **失败处置：** 明确草稿校验失败或中途终止时的保留、重试或升版重发规则；已推送的标签保持原样。

## 客户端更新生命周期

将检查、下载、验签、等待业务收尾、拉起安装、失败与取消建模为独立状态。设置页或弹窗关闭后由后台常驻服务继续管理更新任务，界面重开时拉取最新状态快照；明确并发触发与迟到回调的丢弃规则。

检查、下载、安装准备三阶段分别设置超时上限。进入安装准备阶段后：

1. 暂停新增业务写入，等待进行中的写入任务完成。
2. 回收客户端派生的子进程，刷盘持久化数据与日志。
3. 若用户取消或等待超时，恢复业务写入并回退状态。

退出前的清理钩子位置以所选更新器锁定版本的源码实现为准。同时核对升级契约：用户级与机器级安装权限、UAC 提权、安装路径、应用标识、数据目录与系统凭据库条目标识。存量旧版本不含自动更新器时，设计手动覆盖安装或引导升级路径，并在方案中标注为“首次手动升级”。

## 五级验收阶梯

| 验收层级 | 有效证据 | 证明上限 |
|---|---|---|
| 1. 静态核对 | 锁定依赖源码、权限配置、调用链与构建脚本 | 代码与配置符合方案契约 |
| 2. 协议与状态测试 | 本地受信测试 CA 的 HTTPS 模拟服务、虚构 Token、重定向请求头剥离、超时取消、签名与版本校验失败用例 | 客户端协议、安全边界与状态机正确 |
| 3. 真实检查 | 已安装客户端读取系统凭据库中的真实凭据，正确解析远端 Release 版本 | 真实仓库连通性与鉴权有效 |
| 4. 真实下载与验签 | 已安装客户端完成目标安装包下载，通过版本一致性与签名校验 | 远端资产完整且签名有效 |
| 5. 真实跨版本升级 | 旧版安装包触发更新、完成替换并拉起新版，版本号、业务数据与凭据完整保留 | 端到端自动升级闭环成立 |

仅新增守护真实风险的测试。HTTPS 重定向测试开启完整证书校验（挂载本地受信测试 CA），以测试服务端实际收到的请求头证明跨源时已剥离 `Authorization`。

真实跨版本验收前先备份用户数据目录，升级后比对版本号、业务记录与凭据状态（区分数据库/缓存物理文件变动与业务记录变动）。尚未发布新版本时，如实交付已达成的验收层级，将第 5 级标为待执行。
