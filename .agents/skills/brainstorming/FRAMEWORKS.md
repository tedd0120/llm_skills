# 框架工具箱

**框架是思考工具，不是要填的表。** 一次挑一到两个，能推动对话才用。

| 框架 | 什么时候拿出来 |
|---|---|
| **反演** | 完全卡住，正着想不出来 |
| **第一性原理** | 大家都说"本来就这样"，卡在增量思维里 |
| **How Might We** | 把痛点翻译成可以下手的问题 |
| **Jobs-to-be-Done** | 用户为什么"雇"这个东西，搞不清时 |
| **SCAMPER** | 改造存量产品，需要系统性扫一遍 |
| **机会-方案树** | 从目标一路映射到实验 |

**反演** —— 「怎样才能让这个问题变得更糟？」把「更糟」的每一条倒过来，就是一条改进线索。人识别「什么是错的」比想象「什么是对的」强得多，卡住时这招最灵。

**第一性原理** —— 说清要审视的假设 → 拆到最底层的组件和约束 → 逐个问「为什么非得这样，这是物理定律还是行业习惯」 → 只用剩下的真约束重新搭一遍。

**How Might We** —— 「我们要怎样为 [用户] 实现 [目标]，同时不 [约束]？」
拿捏粒度是关键：「怎样改进新手引导」太宽，等于没说；「怎样在第 3 步加个提示」太窄，那是方案不是问题；「怎样让新用户在 10 分钟内拿到第一个成果」刚好。**一个问题陈述生成 5-10 个 HMW**——每换一种问法，就打开一片不同的解空间。

**Jobs-to-be-Done** —— 「当 [情境] 时，我想要 [动机]，以便 [结果]。」
方案会变，job 不变——为了跟同事同步进展，人们几十年来先后"雇"过备忘录、邮件、Slack、共享文档。功能性的 job 好找；情绪性的（有把握、显得专业）和社交性的（被当成靠谱的人）常常更有劲。关键一问：**「他们是把什么给"解雇"了才用上你的？」**——这才问出了真正的竞品。

**SCAMPER** —— 替换、合并、借用、放大缩小、他用、删除、反转。七个镜头扫存量产品用，挑当下有张力的那两三个就够，其中「删除」和「反转」最常出货。

**机会-方案树** —— 目标 → 机会（用户需求／痛点）→ 方案 → 实验，逐层展开。
机会来自调研，不是想象，每个机会都要能追溯到证据。一个机会只挂了一个方案，说明探得不够。一个方案只挂了一个实验，说明还没找到最便宜的验证法。
