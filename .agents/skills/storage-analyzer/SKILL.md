# Windows 存储分析

扫描文件元数据，按用途分组并说明清理影响，交付一个本机网页：用户勾选后点击清理，或一键调用 Windows 自带工具。需要 Windows 和 Python 3.10+；扫描、分析、离线报告只用标准库，清理服务需要 `pywin32`、`Send2Trash`（见 `requirements.txt`）。

## 执行

`scripts/` 相对于本 skill 目录，执行时使用脚本绝对路径。`<输出目录>` 为本次扫描目录。

1. **只读扫描。** 默认扫描系统盘，`--root` 可限定目录。C 盘约 150 万文件时耗时 1–2 分钟。

   ```powershell
   python scripts/scan.py
   ```

   从输出的 `OUTPUT=` 行取得输出目录。指定位置时用 `--output <新目录>`。

2. **分组并复核。** 读取 [Windows 分类规则](references/windows.md)，然后：

   ```powershell
   python scripts/analyze.py --output <输出目录>
   ```

   终端输出候选总量、优先清理量和系统级可回收量。打开 `report-data.json`，按体积从大到小复核 `groups`：

   - 每组的 `title`、`root`、`parts`（组内最大的子目录）能说明它是什么。
   - 应用名陌生、目录名是 UUID 或版本号时，只读查看目录结构确认归属。
   - 通用规则按 AppData 下的缓存目录名归组；目录名含 Cache 但内容是下载的视频、离线资料时，改为需确认或停用。

   修订写入输出目录的 `decisions.json`，键为组的 `root` 或 `id`，可覆盖 `title`、`why`、`impact`、`level`（`优先清理`/`需确认`）、`category`、`enabled`：

   ```powershell
   python scripts/analyze.py --output <输出目录> --decisions <输出目录>\decisions.json
   ```

   复核完成的标准：每个启用的组用途明确；可能含唯一副本的内容为“需确认”。临时文件天数默认 2 天，可用 `--temp-days` 调整。

3. **生成报告并启动服务。** 清理是本 skill 的核心价值，默认启动服务：

   ```powershell
   python scripts/build_report.py --output <输出目录>
   python scripts/server.py --output <输出目录>
   ```

   打开终端输出的 `http://127.0.0.1:<端口>/`。后台启动时使用当前 Python 绝对路径、独立日志文件和隐藏窗口。用户只要一份可留存的文件时，`report.html` 可离线打开，按钮不可用。

4. **在浏览器验收。** 核对可用空间、连接状态、分类数量；打开再取消一次清理确认弹窗。验收只做查看和取消。

5. **向用户汇报。** 用日常语言给出：当前可用空间、可放心清理的总量、最值得先做的两三件事（通常是清理缓存、清空回收站、处理休眠文件）、风险最高的一项，以及报告地址。

## 网页提供的操作

- **清理文件**：按类别勾选（开发缓存、浏览器与应用缓存、临时文件与日志、旧版本与安装包、媒体缓存），默认选中全部“优先清理”。确认弹窗中选择移入回收站或直接删除；包含“需确认”的组时只能移入回收站。
- **系统与大目录**：清空回收站（Windows 再确认一次）、精简或关闭休眠、磁盘清理、删除旧更新目录、组件清理、打开虚拟内存和应用设置。标“管理员”的操作会弹出 UAC 授权窗口。
- **空间分布**：从磁盘根目录逐层下钻，可在资源管理器中打开任意列出的位置。
- **迁移到其他盘**：存在可用空间大于 30 GB 的其他固定磁盘时，列出缓存目录改位置的命令和文件夹迁移方法。

## 安全边界

- 每个清理和系统操作都需用户在页面确认；Agent 的扫描、复核、验收步骤不代替用户点击确认。
- 文件清理只处理清单中启用的普通文件，目标须同时位于当前用户目录和扫描根下，且大小、修改时间与扫描一致、路径上没有重解析点。
- 组根目录下的子目录若只含清单内未变化的文件，整个目录一次移入回收站或删除；含新增、变化或被占用文件的目录逐个处理文件，不在清单内的文件保持原样。
- 直接删除仅限“优先清理”的组；“需确认”的组只能移入回收站。
- 系统操作由服务端白名单固定命令，只开放本次报告系统卡片中列出的操作。
- 打开位置只接受报告中显示过的路径。
- 操作逐文件写入输出目录的 `operations.jsonl`，已清理的组记录在 `cleaned.json`。

## 清理后刷新

页面的可用空间和回收站大小实时刷新；候选清单停留在扫描时刻。用户说“已经清理了，刷新一下”时，重新执行扫描、分组、生成报告，并启动指向新目录的服务。确认旧服务没有进行中的任务后，按进程命令行中的输出目录核对身份再停止。旧决策文件只迁移仍存在的组。

## 产物与验证

目录优先级：显式 `--output`；`LLM_SKILLS_DATA_DIR/storage-analyzer`（状态用 `LLM_SKILLS_STATE_DIR`）；从脚本位置向上找到的仓库 `data/storage-analyzer`（状态 `.local/storage-analyzer`）；`~/.llm-skills/data/storage-analyzer`（状态 `~/.llm-skills/local/storage-analyzer`）。默认在产出根下新建时间目录。清单含本机私有路径，保持本地保存。

修改脚本后执行 `python scripts/selftest.py --recycle`：覆盖扫描、分类规则、决策覆盖、路径与 HTTP 校验、直接删除，以及测试文件的回收站往返恢复。
