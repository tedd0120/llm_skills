# 高保障收口

本流程扩展核心终态闸门。它适用于 `SKILL.md` 指定的高保障场景。

## 平台边界

该 Skill 是提示词层的缓解措施。它无法清除模型已读上下文，也无法控制透明工具调用、审批提示和宿主生成的界面。

用户要求保护某个宿主无法控制或回读的表面时，在外部变更前说明限制。实质性指令冲突需要停止执行并请求方向。

## 敏感信息

按受众与目的地分类凭据、个人数据、内部代号和机密事实。选择暴露最少且准确的表述。

披露一项事实不自动授权披露其字面值、派生形式、类别或存在性。准确性、法律或审计要求必须使用原值时，先确认获准的目的地。

原始敏感值不得进入生产提示、验证提示、命令文本或工具轨迹。使用可信的 secret 或 DLP 工具做确定性检查。`check_surface.py` 仅处理适合出现在本地 terms 文件中的非敏感词。

## 上下文隔离

强提示污染、委派或上下文压缩场景中，构造净化生产规格。规格只包含：

- 正向目标；
- 权威基线与观察事实；
- 每个表面的受众与必需事实；
- 输出格式与允许修改的文件。

被否方案留给编排方验证。独立 producer 只接收净化规格，并使用没有继承会话、摘要或记忆的新上下文。

无法验证上下文隔离时，在当前上下文按净化规格工作，并将隔离状态记为 best-effort。

## 冻结式收口

1. **Preflight：** 渲染并冻结外部变更前可用的全部表面。记录受众和基线。检查字面残留、语义转述、包装、任务保真与用户改动。
2. **Mutation：** 使用冻结内容执行获准的发送、发布、commit 或 release。执行时保持内容不变。
3. **Readback：** 回读实际产物与元数据。包括 hook 和平台生成的包装。
4. **Postflight：** 复查所有可读表面。根据回读结果生成并验证交接说明。

后续变化会使此前检查失效。变化后从相应检查阶段重新开始。

## 独立验证

有新鲜独立上下文可用时，向 validator 提供冻结表面、非敏感静默项、必需事实、受众和基线分类。validator 只返回结构化 `PASS` 或违规码，并保持产物不变。

验证同时覆盖残留控制与任务保真。Preflight 修复两轮后仍有实质歧义时，在外部变更前请求用户方向。

Postflight 失败时，只在现有授权内修复并重新回读。无法修复或无法读取的状态按事实报告。
