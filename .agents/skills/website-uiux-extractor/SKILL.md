# 网站 UI/UX 视觉令牌提取

把网站转译成可复用的设计系统。提取视觉语言和交互规律，不复制第三方源码、文案、图片或受限字体文件。

## 输入与默认值

- 要求一个可访问的 `http://` 或 `https://` 网址。
- 接受用户指定的页面范围、登录态、视口或输出目录；未指定时覆盖同源公开体验，并输出到 `<cwd>\data\website-uiux-extractor\<site-slug>\`。
- 把“整个 UI/UX”定义为覆盖每种核心页面族、布局断点和可达交互状态，而不是枚举内容相同的每个 URL。
- 仅在用户明确要求且现有浏览器已具备合法登录态时覆盖登录后页面；把未登录、权限不足、地区限制和反爬阻断记录为覆盖缺口。

## 工作流

### 1. 建立覆盖矩阵

1. 用可交互浏览器打开入口网址，确认最终 URL、站点名称、主题和语言。
2. 从主导航、页脚、站内链接和可见流程识别页面族：入口/营销、列表或搜索、详情、表单或转化、账户、帮助，以及弹层、菜单、通知等跨页结构。
3. 每个可达核心页面族至少选一个代表页面。限制在同源站点；外部支付、身份提供商和嵌入式第三方只记录边界。
4. 至少检查桌面 `1440×900` 与移动 `390×844`；当布局在中间宽度发生结构变化时增加 `768×1024`。
5. 对每个核心组件检查适用状态：default、hover、focus-visible、active、selected、disabled、loading、empty、error、success、expanded/open。
6. 为每条观察记录 URL、视口、状态和简短证据。把无法访问或无法可靠测量的部分写入 `coverage.gaps`，不猜值。

页面族、桌面与移动视口、核心组件状态都有记录后，覆盖矩阵才算完成。

### 2. 采集视觉与交互证据

- 同时使用截图和浏览器计算样式：截图用于判断层级、节奏和构图，计算样式用于确认精确值。
- 采集颜色角色、字体族/字号/字重/行高/字距、间距、圆角、边框、阴影、容器宽度、栅格、断点、层级、图标与图像处理。
- 逐类盘点按钮、图标按钮、输入框、文本域、开关、滑块、标签页、卡片和复合输入器；记录可见构造、尺寸、颜色、圆角及已检查状态。没有观察到的组件类型不要补造。
- 观察固定/粘性区域、滚动行为、弹层、响应式重排，以及进入、退出和状态反馈的时长与缓动。
- 优先记录重复出现的系统值；保留少量确有独立语义的非标值。允许同一个原始值服务多个语义角色。
- 记录字体的真实家族名和可用回退栈；只在用户有权使用且明确要求时下载字体或品牌资产。

每个最终令牌和组件规则至少能回指一个页面、视口或状态证据后，采集才算完成。

### 3. 建立单一事实源

在写令牌前完整读取 [references/token-contract.md](references/token-contract.md)。复制 [assets/tokens.example.json](assets/tokens.example.json) 到输出目录，按观察结果改成 `<slug>-tokens.json`：

- 用语义角色命名，如 `primary`、`canvas`、`body-muted`，不要把偶然出现的色值当名称。
- 只写观察到或由多处测量归纳出的值；在描述中区分精确测量与视觉推断。
- 先去重再定稿：合并重复页面、视口、状态、证据、组件和规则；同值同义令牌只留一个；同值异义令牌保留语义名，但用 `{group.canonical-token}` 引用一个规范字面值。
- 把页面、视口、状态、缺口、布局、组件和用法规则写入 `$extensions.com.website-uiux-extractor`。
- 为每个组件填写 `specimen`，把实际观察到的状态映射为原生控件或结构样本；按钮、输入框、开关、滑块和标签页不能只保留属性清单。
- 保留 JSON 中的组件引用格式，如 `{color.primary}`、`{typography.body}`、`{radius.pill}`。

令牌 JSON 是唯一事实源。Markdown、CSS、预览页都由脚本生成，不分别手改。

### 4. 生成产物

把 `<skill-dir>` 解析为本 `SKILL.md` 所在目录，然后运行：

```bash
python "<skill-dir>/scripts/build_package.py" "<output-dir>/<slug>-tokens.json" --output-dir "<output-dir>"
```

首次生成遇到同名文件时换一个空目录；确认这些文件属于本次生成结果后，才使用 `--force` 覆盖。脚本生成：

- `<slug>-DESIGN.md`
- `<slug>-tokens.json`
- `<slug>-variables.css`
- `<slug>-theme.css`
- `<slug>-preview.html`

### 5. 视觉与一致性验证

1. 用 `--check-only` 检查 JSON 契约和覆盖门槛。
   构建脚本自动合并重复观察项，并拒绝同一令牌组内重复写死的值；按报错把非规范项改成别名。
2. 在桌面和移动宽度打开 `<slug>-preview.html`，检查溢出、对比度、字体回退、品牌观感以及组件状态样本。
3. 抽查主色、正文、至少两级字号、间距、圆角、阴影和三个核心组件；确认已采集的按钮、输入框、开关、滑块或标签页以真实控件出现，再与源站对应截图并排比较。
4. 确认两份 CSS 的变量名和值一致，Markdown 与预览只展示 JSON 中的值，五个产物均非空。
5. 修正唯一事实源并重新生成；不要直接修补派生产物。

只有产物齐全、预览在桌面与移动宽度可读、抽查无冲突、覆盖缺口已明确记录时才交付。

## 交付说明

提供五个产物的路径，并用三点概括：视觉语言、已覆盖页面/视口/状态、仍存在的覆盖缺口。把结果称为“截至采集时间的快照”，提醒实现时以当前源站为准。
