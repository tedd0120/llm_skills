# 小红书报告格式化组件

> ⚠️ **内部组件** — 本组件仅由 `xiaohongshu-scraper` 内部调用。

对调用方（scraper）传入的 `REPORT_FILE`（`{OUTPUT_DIR}/{主题}.md`）进行后处理，增强 emoji、替换超链接占位符、清理格式标记。本组件不自行推导文件名。

## 执行流程

1. **读取现有报告**
   - 读取 `REPORT_FILE` 全部内容
   - 检查 OUTPUT_DIR 下是否存在 `id_url_map.json`

2. **URL 替换（超链接功能）**

   如果 `id_url_map.json` 存在：
   - 读取 ID-URL 映射文件，获取所有有效的 post_id
   - 将报告中的所有 `(id:{post_id})` 占位符替换为帖子详情页 URL：`(id:{post_id})` → `(https://www.xiaohongshu.com/explore/{post_id})`
   - 映射文件用于验证 post_id 存在性，URL 使用 `explore` 格式构造

3. **应用格式化**
   - 按下方 emoji 规范增强格式
   - 若存在「搜索发散路径」板块，按发散路径规则专门处理
   - 确保主要板块之间使用 Markdown 分割线（`---`）；子章节之间不加
   - 按清理规则清除用户评论中的小红书格式标记
   - 保持原有内容和结构不变

4. **覆盖原文件**：将格式化后的内容写回 `REPORT_FILE`

## Emoji 使用规范（Moderate 风格）

原则：适度使用、语义相关、保持数据分析报告的专业感。具体 emoji 由 Agent 根据内容上下文自行判断。

### 必须使用 Emoji 的位置

| 位置 | 示例 | 说明 |
|:-----|:-----------|:-----|
| 报告标题 | ☕️ 北京咖啡厅探店报告 ☕️ | 前后各一个 |
| 主要板块标题 | 📊 搜索概览、🔥 声量分析、💬 高频共识、📍 数据来源说明 | 标题前加一个 |
| 场景推荐表格 | ☕ Dirty首选、📚 自习办公 | 场景列加 emoji |
| 避雷问题类型 | 🚫 空间问题、💸 价格问题 | 问题分类标识 |
| 优缺点列表前缀 | ✨ 核心优点、😤 核心痛点 | 列表标题 |
| 关键洞察编号后 | 1. ☕ Dirty是... | 每条洞察一个 |
| 表格内的评级 | ⭐⭐⭐⭐⭐ | 质量评分 |
| 热度指示 | 🔥🔥🔥 | 3-5个火焰表示热度 |

### 不使用 Emoji 的位置

- 引用的用户评论内容（保持原始感）
- 来源标注行
- 长段落正文
- 价格档位（保持清晰简洁）

### 发散路径板块规则

当报告包含「搜索发散路径」板块（识别标题 `## 搜索发散路径`，兼容带 emoji 的标题）时：

- 仅处理该板块的表格样式与可读性，不修改原始数据语义
- 保持列结构不变：`轮次 | 关键词 | 实际篇数 | 发散理由`
- 关键词列可按语义补充前缀 emoji；发散理由列可用轻量 emoji（如 💡 新发现、🔁 迭代延伸）
- `合计` 行保持简洁，不堆叠 emoji
- 禁止更改关键词和理由的核心文本含义，仅允许前后缀增强
- 如果报告无该板块，跳过并继续处理其他板块

## 清理规则

小红书评论中，回复他人的评论会带有 `":"` 前缀，需要移除：

- 匹配模式：`_(":"` → 替换为 `_("`
- 只在用户评论（斜体引号包裹的内容）中应用
- 不影响其他位置的 `":"` 符号

## 格式化示例

```markdown
# 北京咖啡厅探店报告
## 搜索概览

↓ 格式化后

# ☕️ 北京咖啡厅探店报告 ☕️
## 📊 搜索概览
```

数据来源说明板块：仅在标题前加 📍，免责声明文本、生成时间、工具版本**原样保留，禁止改写**。
