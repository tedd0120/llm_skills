# 项目初始化与规范补全（init）

读取 [templates/AGENTS.md](templates/AGENTS.md) 作为通用规范正本，使用文件读写与编辑工具完成目标项目的初始化或增量补全。

## 全新项目初始化

目标项目根目录不存在 `AGENTS.md` 与 `CLAUDE.md` 时：

1. 将 [templates/AGENTS.md](templates/AGENTS.md) 写入根目录 `AGENTS.md`。
2. 在根目录创建 `CLAUDE.md`，写入 `@AGENTS.md`。
3. 检查根目录 `.gitignore`，缺失 `.work/` 或 `.local/` 时追加。

## 存量项目查漏补缺

目标项目根目录已存在 `AGENTS.md` 或 `CLAUDE.md` 时，模板与既有文档逐条融合：既有文档的结构、措辞与业务规则是主体，模板条文按语义织入对应位置。按以下顺序执行：

1. **通读既有文档**：完整读取 `AGENTS.md` 与 `CLAUDE.md`，记录板块结构、条文主题、语言风格、业务规则与自定义规则，以及两个文件之间的重复内容。
2. **逐条比对分类**：模板的每条规则（共 9 个板块）对照既有文档的全部条文，判定为以下四类之一：
   - **已覆盖**：既有条文语义等价（措辞不同也算），保留既有写法。
   - **缺失**：既有文档没有任何涉及该主题的条文。
   - **冲突**：同一主题的规则与模板相反或相互排斥（如既有文档允许自动 `git commit`，模板要求用户明确要求）。
   - **模糊**：无法确定语义是否等价、无法确定应归入既有哪个板块，或既有文档使用 `docs/plans`、`.prototype/`、`.prototypes/`、`.tmp/` 等旧产物目录而与 `.work/` 约定并存。
3. **集中确认**：冲突项与模糊项合并成一次提问交给用户，每项列出既有写法、模板写法与建议处理（保留既有、采用模板或合并措辞）。用户答复前不修改任何文件。旧产物目录的存量迁移提示用户使用 `workspace-layout` 技能。
4. **按语义融合**：
   - 缺失条文写入既有文档中主题最贴近的板块，保持该板块现有的行文风格与编号方式。
   - 整个主题缺失时，新建板块并放在与其相关的既有板块之后，板块顺序服从既有文档。
   - 冲突项与模糊项按用户答复处理。
   - `CLAUDE.md` 的独立业务规则并入 `AGENTS.md` 对应板块，`CLAUDE.md` 顶部保留 `@AGENTS.md` 单行引用。
5. **`.gitignore` 规则补齐**：缺失 `.work/` 或 `.local/` 时追加至文件末尾。
6. **变更回显**：向用户列出每条模板规则的去向（已覆盖、已织入的位置、按答复处理的冲突与模糊项）以及保留的既有板块。
