# 存量项目查漏补缺指引（Patch & Audit）

当项目根目录已存在 `AGENTS.md` 或 `CLAUDE.md` 时，禁止强行覆盖，应按本指引执行增量审查与补全，完整保留既有业务规范。

## 审查维度与基准项

### 1. `CLAUDE.md` 单真源检查
- **检查项**：是否包含 `@AGENTS.md`。
- **补全动作**：若缺少，在文件顶部追加 `@AGENTS.md` 及单真源说明；若已存在引用，保持原样。

### 2. `AGENTS.md` 通用规则检查
逐项核对是否具备以下 6 个通用规则板块（识别标题或核心语义）：

| 序号 | 标准板块 | 核心识别语义 | 缺失时的补齐内容 |
|:---:|:---|:---|:---|
| 1 | 语言 | 默认简体中文，专业名词保留英文 | 追加 `## 语言` 段落 |
| 2 | Git 操作 | 默认只读查询，变更需明确要求，破坏性操作需授权 | 追加 `## Git 操作` 段落 |
| 3 | 任务规划与执行状态 | 写入 `docs/plans/`，划分阶段，初始化并实时更新状态 | 追加 `## 任务规划与执行状态` 段落 |
| 4 | 原型产物 | 产物放 `.prototype/{时间戳_主题}/`，standalone 入口 | 追加 `## 原型产物` 段落 |
| 5 | 代码检索 | 包含 `.codegraph/` 时优先用 CodeGraph | 追加 `## 代码检索` 段落 |
| 6 | Skill 规范 | 渐进式披露原则：主干写入 `SKILL.md`，不同场景/互斥分支在 `references/` 下各自独立建档 | 追加 `## Skill 规范` 段落 |

### 3. 工程目录与配置补齐
- **`docs/plans/`**：若不存在，创建该目录并在其下放置 `.gitkeep`。
- **`.gitignore`**：检查是否忽略 `.prototype/`，缺失时追加。

---

## 补全原则

1. **非侵入式保留**：既有项目原有的架构说明、数据源、业务命名或自定义规范一律原样保留。
2. **增量末尾追加**：仅在文件末尾追加缺失的通用板块，不修改既有段落文字。
3. **显式回显差异**：每次补齐时，向用户清晰列出：“[已保留] 既有配置”与“[已补齐] 缺失板块”。
