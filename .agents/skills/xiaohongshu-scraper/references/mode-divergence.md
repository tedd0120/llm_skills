# 模式 B（发散模式）：交互与执行规范

本文件定义模式 B 在澄清阶段的专属轮次及执行阶段的多轮流转约束。逐轮交互约束（每轮一个问题）同样适用。

## 阶段一：分支专属轮次

用户回复篇数上限后，依次进行两轮：

### 1. 发散轮数询问

```markdown
发散几轮？（默认 3，范围 2-10）
```

### 2. 配额预览与确认询问

```markdown
配额分配预览：
- 总上限 50 篇，发散 3 轮
- 每轮配额 = 总上限 ÷ 轮数，余数加到第一轮
- 本次分配: [18, 16, 16]
- 报告形态：[推断的中文名]（`REPORT_TYPE`）

确认按该参数开始发散搜索吗？你也可以直接覆盖报告形态。
```

用户确认后进入速度模式轮。

---

## 阶段二：发散模式执行约束

**[核心要求] 禁止提前预设关键词**：
- 禁止在任意轮次开始前预设后续轮次的关键词。
- 每个关键词必须在上一轮搜索完成后根据实际结果确定。

**[核心要求] 每轮必须输出发散决策报告**：
第 N 轮搜索完成后（N < 总轮数），必须向用户展示决策报告：

```markdown
### 第 N 轮发散决策

**本轮发现**：
- 高频品牌/主题：[发现 1、发现 2...]
- 争议焦点：[xxx]
- 信息盲区：[xxx]

**下一关键词**：xxx

**衍生理由**：基于 [具体发现]，为 [目的] 衍生出此关键词
```

*理由示例*：
- 正确：基于发现“品牌A被高频提及且口碑较好”，为进一步了解“品牌A的具体优缺点”，衍生关键词“品牌A 评测”。
- 错误：进一步了解品牌A（缺少因果链）。

---

## 发散模式执行流程

1. **第 1 轮**：
   - 基于用户原始主题生成初始关键词；
   - 调用 fetch 抓取（使用 `--seen-ids <OUTPUT_DIR>/seen_ids.txt` 跨轮去重）；
   - 输出第 1 轮发散决策报告。

2. **第 2 轮 ... 第 N-1 轮**：
   - 使用上一轮决策报告中的关键词；
   - 调用 fetch 抓取；
   - 输出本轮发散决策报告。

3. **最后一轮**：
   - 使用上一轮决策报告中的关键词；
   - 调用 fetch 抓取；
   - 按照 [multi-round-merge.md](multi-round-merge.md) 合并所有轮次数据为 `raw.json`，并写入 `divergence_path`。
