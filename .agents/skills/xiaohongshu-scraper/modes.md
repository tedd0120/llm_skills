# 搜索模式分支：交互轮次与执行约束

本文件是 SKILL.md 澄清阶段"分支专属轮次"的详细定义，以及发散模式在执行阶段的约束。逐轮交互约束（每轮一个问题）同样适用于本文件所有轮次。

## 模式 A（固定关键词）：分支专属轮次

用户回复篇数上限后，进入**关键词衍生与确认**轮：

根据篇数上限衍生搜索关键词并展示：

```markdown
我基于你的建议衍生了以下 3 个搜索词：

| 序号 | 关键词 | 预计篇数 | 搜索理由 |
|:----:|:------|:--------:|:---------|
| 1 | [关键词一] | 10篇 | [理由一] |
| 2 | [关键词二] | 10篇 | [理由二] |
| 3 | [关键词三] | 10篇 | [理由三] |
| **总计** | — | **30篇** | — |

报告形态：[推断的中文名]（`REPORT_TYPE`）

你可以：修改单个关键词、调整数量、重新生成、覆盖报告形态、或确认开始爬取。
```

等待用户回复，循环调整直到用户确认（"确认"、"开始"、"好的"、"就这样"等），再进入速度模式轮。

## 模式 B（发散模式）：分支专属轮次

用户回复篇数上限后，依次进行两轮：

**发散轮数询问**：

```markdown
发散几轮？（默认 3，范围 2-10）
```

**配额预览 + 确认询问**：

```markdown
配额分配预览：
- 总上限 50 篇，发散 3 轮
- 每轮配额 = 总上限 ÷ 轮数，余数加到第一轮
- 本次分配: [18, 16, 16]
- 报告形态：[推断的中文名]（`REPORT_TYPE`）

确认按该参数开始发散搜索吗？你也可以直接覆盖报告形态。
```

用户确认后进入速度模式轮。

## 发散模式执行约束（阶段二）

**[核心要求] 禁止提前预设关键词**：
- 禁止在任意轮次开始前预设后续轮次的关键词
- 每个关键词必须在上一轮搜索完成后才能确定
- 禁止在内心或笔记中规划好所有轮次的关键词

**[核心要求] 每轮必须输出发散决策报告**：第 N 轮搜索完成后（N < 总轮数），必须向用户展示"发散决策报告"。

**发散决策报告格式**：

```markdown
### 第 N 轮发散决策

**本轮发现**：
- 高频品牌/主题：[发现 1、发现 2...]
- 争议焦点：[xxx]
- 信息盲区：[xxx]

**下一关键词**：xxx

**衍生理由**：基于 [具体发现]，为 [目的] 衍生出此关键词
```

**衍生理由示例**：

```
✓ 正确示例：
  基于发现"品牌A被高频提及且口碑较好"，为进一步了解"品牌A的具体优缺点"，衍生关键词"品牌A 评测"

✗ 错误示例：
  进一步了解品牌A（缺少因果链）
```

## 发散模式执行流程

```
第 1 轮：
  → 基于用户原始主题生成初始关键词
  → 调用 fetch 抓取（--seen-ids 跨轮去重）
  → 输出发散决策报告

第 2 轮 ... 第 N-1 轮：
  → 使用上一轮决策报告中的关键词
  → 调用 fetch 抓取
  → 输出发散决策报告

最后一轮：
  → 使用决策报告中的关键词
  → 调用 fetch 抓取
  → 合并所有轮次数据为 raw.json
```

合并时按轮次顺序拼接帖子，并复用 fetch 的内容指纹规则（规范化作者 + 标题 + 正文前 300 字）保留首次出现的记录；禁止让 LLM 判断重复。最终 `dedup.posts_scraped` 为各轮原始抓取数之和，`posts_unique` 为最终帖子数，`dropped_duplicate = posts_scraped - posts_unique`，`dropped_id_mismatch` 为各轮之和。
