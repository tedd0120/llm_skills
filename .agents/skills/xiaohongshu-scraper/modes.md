# 搜索模式分支：交互轮次与执行约束

本文件是 SKILL.md 澄清阶段"分支专属轮次"的详细定义，以及发散模式与总分模式在执行阶段的约束。逐轮交互约束（每轮一个问题）同样适用于本文件所有轮次。

## 模式 A（固定关键词）：分支专属轮次

用户回复篇数上限后，进入**关键词衍生与确认**轮：

根据篇数上限衍生搜索关键词并展示：

```markdown
我基于你的建议衍生了以下 3 个搜索词：

| 序号 | 关键词 | 预计篇数 | 搜索理由 |
|:----:|:------|:--------:|:---------|
| 1 | [关键词一] | 10篇 | [理由一] |
| 2 | [关键词二] | 10篇 | [理由二] |
| 3 | [关键词三] | 10篇 | [理由三] |
| **总计** | — | **30篇** | — |

报告形态：[推断的中文名]（`REPORT_TYPE`）

你可以：修改单个关键词、调整数量、重新生成、覆盖报告形态、或确认开始爬取。
```

等待用户回复，循环调整直到用户确认（"确认"、"开始"、"好的"、"就这样"等），再进入速度模式轮。

## 模式 B（发散模式）：分支专属轮次

用户回复篇数上限后，依次进行两轮：

**发散轮数询问**：

```markdown
发散几轮？（默认 3，范围 2-10）
```

**配额预览 + 确认询问**：

```markdown
配额分配预览：
- 总上限 50 篇，发散 3 轮
- 每轮配额 = 总上限 ÷ 轮数，余数加到第一轮
- 本次分配: [18, 16, 16]
- 报告形态：[推断的中文名]（`REPORT_TYPE`）

确认按该参数开始发散搜索吗？你也可以直接覆盖报告形态。
```

用户确认后进入速度模式轮。

## 模式 C（总分模式）：分支专属轮次

用户回复篇数上限后，进行一轮**宏观关键词与配额确认**：

```markdown
基于你的主题，我选定宏观关键词：[关键词]（[选取理由：如何覆盖主题全貌]）

配额分配预览：
- 总上限 [N] 篇，总分 6 轮（1 轮宏观 + 5 轮 top5）
- 第 1 轮（宏观）：[X1] 篇
- 第 2-6 轮（top5，由第 1 轮结果总结得出）：各 [X2] 篇
- 报告形态：[推断的中文名]（`REPORT_TYPE`）

确认按该参数开始总分搜索吗？你可以修改宏观关键词、覆盖报告形态，或确认开始。
```

**配额规则**：
- 第 1 轮配额 = 总上限 × 50%，top5 各轮配额 = 总上限 × 10%，均向下取整，余数加到第 1 轮
- 总上限取用户给出的具体数字，无上限时按默认 100 计
- 总上限低于 10 篇时 top5 各轮配额为 0，应提示用户调高上限或改选模式

宏观关键词由你基于用户主题生成，选取覆盖主题全貌的宽泛搜索词。用户确认后进入速度模式轮。

## 发散模式执行约束（阶段二）

**[核心要求] 禁止提前预设关键词**：
- 禁止在任意轮次开始前预设后续轮次的关键词
- 每个关键词必须在上一轮搜索完成后才能确定
- 禁止在内心或笔记中规划好所有轮次的关键词

**[核心要求] 每轮必须输出发散决策报告**：第 N 轮搜索完成后（N < 总轮数），必须向用户展示"发散决策报告"。

**发散决策报告格式**：

```markdown
### 第 N 轮发散决策

**本轮发现**：
- 高频品牌/主题：[发现 1、发现 2...]
- 争议焦点：[xxx]
- 信息盲区：[xxx]

**下一关键词**：xxx

**衍生理由**：基于 [具体发现]，为 [目的] 衍生出此关键词
```

**衍生理由示例**：

```
✓ 正确示例：
  基于发现"品牌A被高频提及且口碑较好"，为进一步了解"品牌A的具体优缺点"，衍生关键词"品牌A 评测"

✗ 错误示例：
  进一步了解品牌A（缺少因果链）
```

## 发散模式执行流程

```
第 1 轮：
  → 基于用户原始主题生成初始关键词
  → 调用 fetch 抓取（--seen-ids 跨轮去重）
  → 输出发散决策报告

第 2 轮 ... 第 N-1 轮：
  → 使用上一轮决策报告中的关键词
  → 调用 fetch 抓取
  → 输出发散决策报告

最后一轮：
  → 使用决策报告中的关键词
  → 调用 fetch 抓取
  → 合并所有轮次数据为 raw.json（规则见「多轮模式合并规则」）
```

## 总分模式执行约束（阶段二）

**[核心要求] 禁止提前预设 top5**：top5 关键词只能在第 1 轮抓取完成后，基于实际帖子与评论归纳得出。

top5 从第 1 轮结果中提及最多的品牌/主题/子话题中取前 5，关键词由对象名与搜索意图词组成（如"品牌A 评测"、"品牌B 值得买吗"）。

**[核心要求] 第 1 轮完成后必须输出总分决策报告**：展示宏观发现与 top5 及入选理由，随后按报告顺序执行第 2-6 轮。

**总分决策报告格式**：

```markdown
### 第 1 轮总分决策（宏观 → top5）

**宏观发现**：
- 高频品牌/主题：[发现 1、发现 2...]
- 争议焦点：[xxx]
- 信息盲区：[xxx]

**top5 关键词**：

| 序号 | 关键词 | 入选理由 |
|:----:|:------|:---------|
| 1 | [关键词] | [理由] |
| 2 | [关键词] | [理由] |
| 3 | [关键词] | [理由] |
| 4 | [关键词] | [理由] |
| 5 | [关键词] | [理由] |

接下来按上表顺序，以每词 [X2] 篇配额依次抓取 top5。
```

**入选理由示例**：

```
✓ 正确示例：
  基于发现"品牌A被高频提及且口碑较好"，为评估"品牌A是否值得买"，入选关键词"品牌A 值得买吗"

✗ 错误示例：
  了解品牌A（缺少因果链）
```

## 总分模式执行流程

```
第 1 轮（宏观）：
  → 使用澄清阶段确认的宏观关键词
  → 调用 fetch 抓取（--seen-ids 跨轮去重）
  → 基于本轮帖子与评论归纳 top5 关键词
  → 输出总分决策报告

第 2-6 轮（top5）：
  → 按决策报告顺序依次使用 top5 关键词
  → 调用 fetch 抓取（--seen-ids 跨轮去重）
  → 6 轮完成后合并所有轮次数据为 raw.json（规则见「多轮模式合并规则」）
```

## 多轮模式合并规则（发散 / 总分）

按轮次顺序拼接帖子，并复用 fetch 的内容指纹规则（规范化作者 + 标题 + 正文前 300 字）保留首次出现的记录；禁止让 LLM 判断重复。最终 `dedup.posts_scraped` 为各轮原始抓取数之和，`posts_unique` 为最终帖子数，`dropped_duplicate = posts_scraped - posts_unique`，`dropped_id_mismatch` 为各轮之和。

合并后的 raw.json 追加路径字段供报告还原各轮搜索：发散模式写 `divergence_path`，总分模式写 `overview_detail_path`，每轮一条，含 `round`、`keyword`、`actual_posts`、`note`（发散理由 / 宏观说明或 top5 入选理由）。
