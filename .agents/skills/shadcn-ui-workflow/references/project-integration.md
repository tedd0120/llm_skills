# 项目适配约定

## 确认项目上下文

- 读取目标项目的 Agent 指引、UI 规范及设计令牌文档（如有），定位现有组件、样式入口和验证设施。
- 以目标应用的 components.json、依赖清单和锁文件确定安装路径、别名、组件风格、基础库与版本；缺少配置时先确认框架兼容性及现有接入方式。
- 优先复用本地组件和工具函数。采用上游源码前比较本地定制，保持每个复合组件的 Root、Trigger、Popup 等来自同一基础库。
- 页面布局在业务层组合；调整基础组件前检查所有调用方。

## 样式接入

- 复用项目现有语义令牌、主题和字体入口。核对同名变量的真实含义，再映射上游样式需要的颜色与尺寸。
- 检查 CSS 入口、层叠顺序和全局重置策略；新增组件按需补充基础样式，避免全局变更影响既有界面。
- CLI 添加后审查源码、CSS、依赖和锁文件差异，特别检查 body 样式、主题变量与 Preflight。
- 按项目支持的主题与屏幕尺寸验证可读性、对齐和焦点可见性。

## 运行环境与交互

- 按目标框架适配路由、链接、字体、资源入口和服务端渲染边界；先确认示例依赖的运行环境。
- 弹层检查 Portal 容器、层级、滚动、Esc 关闭、焦点限制与恢复，以及嵌套弹层的关闭顺序和页面快捷键。
- 有退出动画时，协调动画与弹层生命周期，确认关闭后焦点限制及时解除。
- Electron 项目额外检查标题栏交互控件的 `-webkit-app-region: no-drag`、窗口拖拽区域及宿主快捷键；浏览器项目按其实际运行环境验收。
- 保持可访问标签、受控状态及业务回调语义，用真实键盘或 pointer 交互验证自定义控件。

## 验证

- 使用目标项目提供的类型检查、构建和 UI 验证设施，覆盖本次受影响的组件与调用方。
- 检查默认、悬停、焦点、禁用及相关展开状态；有交互时实际操作验证。
- 将项目专属实现与验证命令记录在目标项目文档中，交付时区分已验证结果与未验证项目。
