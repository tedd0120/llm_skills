# 数据分析（data-analysis）

> **何时在这里**：面对一个**数据集**，要从中得出结论——统计、找规律、对比、算指标、支撑一个论断。
> 区分线：答案在外部世界要检索 → `research.md`；要理解产生数据的代码逻辑 → `comprehension.md`；要基于结论做取舍 → `decision.md`。

## 崩点

**垃圾进，垃圾出。** 头号风险是**没验证数据质量就开始分析**——口径不一、缺失、重复、异常值、埋点断档，会让漂亮的图表得出完全错误的结论，而且错得很有说服力。第二杀手是**把相关当因果**。第三是**被聚合数字骗**（辛普森悖论：整体趋势与分组趋势相反）。任何数字在你信它之前，都得先过一遍**合理性检查**（sanity check）：它和你已知的真值对得上吗？

## 框架（重心：勘察验数 + 验证 sanity check）

- **框定** — 明确要回答的**业务/研究问题**与判定标准，以及需要多细的答案（一个总量？还是分渠道趋势？）。
  - · 判据：能把问题写成"要得到关于 X 的什么结论、精确到什么程度"。
- **勘察** — 摸清数据来源、**口径**（时区/单位/定义/去重规则）、时间范围、**缺失/异常/重复/断档**。**先验数据质量，再分析**。
  - 怎么验：看每个关键字段的分布、空值率、去重前后条数、时间连续性（有没有某天突然为 0——多半是埋点/管道故障而非真实）。
  - · 判据：知道数据的分布、缺失、明显异常，并已对齐口径。
- **谋划** — 选方法（描述 / 对比 / 相关 / 分群 / 建模）与验证方式；写下你的**假设**与"什么结果会推翻它"。
- **执行** — 探索 → 分析；每一步做完整性与合理性检查（量级对吗、边界对吗、有没有空值/重复污染结果）。
- **验证** — 结果过 **sanity check**：与已知基准/常识对齐（"总量对得上吗"）；检验对**切分、异常值**是否稳健；**不把相关当因果**；分群看有没有辛普森反转。
  - · 判据：核心数字能与一个独立锚点对上，且换个切法结论不崩。
- **收尾** — 用清晰的可视化/表达呈现结论 + **口径 + 局限 + 不确定性**。

## 关键手法

- **先画分布再动手**：对关键字段先看直方图、空值率、min/max、去重前后条数——先认识数据长什么样，异常一眼就露。
- **对齐口径**：时区、单位、货币、"活跃/新增/留存"的定义、是否去重——口径不一是错误结论的头号来源，跨表对比前必须先统一。
- **已知锚点校验**：把算出的总量/均值和一个你独立已知的真值对一下（"昨天订单数和运营看板对得上吗"）；对不上，先别信自己的数。
- **相关 ≠ 因果**：发现相关，先想混淆变量、反向因果、选择偏差，再谨慎措辞；能做对照/分群就别只看总相关。
- **分群防悖论**：整体结论要在关键分群里再看一遍，防辛普森悖论（整体涨、每个分群其实在跌）。
- **报不确定性**：样本量、置信区间、"这只是相关"——别给点估计披上确定的外衣。
- **可复现**：清洗与转换步骤写成脚本/记录，别在电子表格里手改到无法复现。

## 反模式（含识别信号）

- ❌ 不验数据质量直接分析 — _信号：你拿到表就开始 group by，没先看缺失/异常_ → ✅ 先查缺失/异常/口径/断档
- ❌ 相关当因果、随口归因 — _信号：你说"A 导致 B"但只有一条相关性_ → ✅ 想混淆变量、谨慎措辞
- ❌ 只报点估计不谈不确定性 — _信号：给了一个精确数字却没提样本量/区间_ → ✅ 报样本量/区间/局限
- ❌ 口径不一致还硬比 — _信号：两个表的"用户数"定义其实不同，你直接相减_ → ✅ 先统一定义
- ❌ 聚合一个数字掩盖分组差异 — _信号：只看总体，没分渠道/时段/人群_ → ✅ 分群交叉验证

## 走一遍（示例）

> 问题："上月用户留存率大跌，为什么？"
> **框定**：要定位下跌是真实的还是数据问题，并找出可归因的分群；判定标准=能对下跌给出有证据的解释。
> **勘察**：先验数据质量——看每日留存的时间序列，发现从 15 号起某主要渠道的数据**突然掉到接近 0**且再没回来。这不像真实用户行为（不会一夜归零），更像埋点/管道断档。
> **谋划**：假设"下跌主要来自该渠道的数据缺失，而非真实留存下降"。可推翻它的检查：把该渠道剔除后，其余渠道留存是否平稳？
> **执行**：分渠道拆解 → 除该渠道外，其余渠道留存基本平稳；该渠道 15 号后数据缺失。
> **验证**：sanity check——把"总留存"和"剔除问题渠道后的留存"对比，后者与历史锚点吻合；确认是**埋点断档**导致的口径问题，不是真实留存崩盘。避免了"相关（时间上同时发生）当因果"。
> **收尾**：结论=下跌主要是该渠道 15 号埋点故障造成的统计假象，真实留存平稳；附口径说明与"该渠道数据需修复后重算"的局限；建议先修埋点。

## 完成的定义

- [ ] 数据质量（缺失/异常/重复/口径/断档）已验证并记录
- [ ] 核心结论过 sanity check、与独立基准对齐
- [ ] 结论对切分与异常值稳健（换个切法、分群看不崩）
- [ ] 相关性未被冒充因果，措辞谨慎
- [ ] 口径、局限、不确定性已随结论说明，分析可复现
