# 实现功能（implementation）

> **何时在这里**：给系统**新增能力**——加一个功能、做一个 X、或从头搭一个新项目/原型。
> 两个分支：**融入既有代码库**（找缝、顺架构）与**从零开始**（greenfield：先立走骨架）。下面分别标注。
> 区分线：修坏的 → `debugging.md`；接外部系统 → `integration.md`；只做能自动跑的工具 → `automation.md`。

## 崩点

**最大的浪费是"实现了字面需求，却没解决真实意图"。** 用户说出的是他想到的解法表象，要的是背后的目的——照着字面做，常常做完才发现南辕北辙。第二个崩点：**不顺着既有架构的"缝"（seam）硬塞**，写出与仓库格格不入、下一个人看不懂、和现有约定打架的代码。一致性 > 个人偏好：仓库已有的模式，哪怕不是你最爱的，也照着写。

## 框架（重心：框定意图 + 执行曳光弹）

- **框定** — 挖出**真实意图**与**验收标准**（完成的定义），划清边界与**非目标**，做**右尺寸**判断。
  - 挖意图：问"这个功能被用来达成什么"，而非只接"要一个按钮"；模糊处选合理默认并明说（让用户可复核、可推翻），或直接澄清。
  - · 判据：说得清"做完后用户能做到什么、什么明确不做"。
- **勘察** —
  - _融入既有_：定位相关代码、约定、缝、**相似先例**（仓库里有没有做过类似的事？照它的分层/命名/错误处理写）。
  - _从零_：明确**最小可用切片**，选型对齐目标而非新潮。
  - · 判据：知道该改/新建哪些文件，且手上有一个可模仿的范式。
- **谋划** — 设计**最小可行方案**；_从零_ 时先规划**走骨架**（walking skeleton：端到端最薄一条线先跑通）。分解为可独立验证的小块，接口先定。
- **执行** — 打**曳光弹**：先让最薄的一条端到端真的跑起来（中间可先硬编码占位），再逐块换成真实逻辑；全程跟随既有代码风格与约定，小步可运行。
- **验证** — 对照验收标准**逐条**验证；跑 happy path + 边界（空、超长、非法、并发）；**运行真实场景**而非只读代码自我说服。
  - · 判据：每条验收标准都被实际跑通验证过。
- **收尾** — 按需补测试与文档/注释；集成入口清晰；清理脚手架与调试残留。

## 关键手法

- **照抄仓库现有模式**：动手前先找一个最相似的已有功能，把它的分层、命名、错误处理、测试写法当模板——省未来所有人的心智，也最不容易埋坑。
- **走骨架（walking skeleton）**：_从零_ 时先要一具"能端到端呼吸"的最小骨架（UI→逻辑→存储 哪怕全是占位），再往上长肉——这是防"各模块最后拼不起来"的最强手段。
- **曳光弹增量**：每一步都保持可运行、可交付；先打通再加厚，而不是憋一个大改一次点亮。
- **接口先行**：先把输入输出/函数签名/数据结构定清楚，再填实现，让调用方能并行推进。
- **YAGNI**：只做当前需求要的；不为想象中的未来加抽象、加配置、加扩展点。
- **边界清单**：实现前列出这个功能的边界输入（空、零、极大、并发、非法、超时），实现时就照顾到，而非事后补。

## 反模式（含识别信号）

- ❌ 解字面需求 — _信号：你没问"这用来干嘛"就开始写_ → ✅ 先挖真实意图与验收标准
- ❌ 另起炉灶不合群 — _信号：你的写法和隔壁同类功能长得完全不一样_ → ✅ 顺既有约定与先例
- ❌ 憋大招一次写完再跑 — _信号：几百行了还没跑过一次_ → ✅ 曳光弹增量、每步可运行
- ❌ 过度设计 — _信号：为"以后可能要"加了没人要求的抽象层/配置_ → ✅ YAGNI / 右尺寸
- ❌ 读完代码就宣布"应该没问题" — _信号：你没真跑就说完成_ → ✅ 跑真实场景验证

## 走一遍（示例）

> 需求：给订单后台加"导出当前筛选结果为 CSV"。
> **框定**：真实意图=运营要把筛选后的订单拿去 Excel 分析；验收=点导出得到当前筛选条件下所有订单的 CSV，字段与列表一致；非目标=不做异步大文件/邮件推送。
> **勘察**：仓库里已有"导出 PDF"的先例 → 照它的 controller/service 分层、权限校验、文件下载响应方式来写；复用它的筛选条件解析。
> **谋划**：走骨架——按钮 → 新接口 `/orders/export` → 先返回一行硬编码 CSV，端到端打通下载。
> **执行**：骨架通了以后，把硬编码换成真实数据：复用列表的查询（带筛选），映射成 CSV 行；跟随既有代码风格。
> **验证**：逐条对验收——筛选生效、字段对齐；边界：空结果（导出只有表头）、字段含逗号/换行（正确转义引号）、大结果集（不超时）。真点按钮下载打开确认。
> **收尾**：补一条"含特殊字符转义"的测试；删掉骨架期的硬编码与调试日志。

## 完成的定义

- [ ] 每条验收标准都已实际跑通验证
- [ ] happy path 与关键边界（空/超长/非法/并发）都覆盖
- [ ] 代码风格、分层、命名与仓库既有约定一致
- [ ] 无死代码 / 调试残留 / 脚手架
- [ ] 集成/调用入口清晰，必要的测试与文档已补
