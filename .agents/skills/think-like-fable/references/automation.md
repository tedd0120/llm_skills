# 自动化脚本（automation）

> **何时在这里**：把**重复的手工劳动**变成可托付的自动化——脚本、批处理、CI/CD 流水线、定时任务、数据管道。
> 区分线：一次性探查、跑完即弃、无需健壮性的，按右尺寸原则直接做掉即可，不必上这套；对接外部 API 的重心在边界 → `integration.md`。脚本要**改生产数据**（修数/回填）→ 本 play 的 dry-run 与幂等之外，叠加 `ops.md` 的纪律：先备份、小批量灰度、可回滚。

## 崩点

**一次性脚本和"可托付的自动化"是两回事。** 你写完就丢的脚本，和一个别人半夜会依赖、失败了没人盯着的自动化，标准天差地别。自动化的三大敌人：**非幂等**（重跑就出错/重复）、**静默失败**（错了不吱声，下游拿到脏数据还以为没事）、**只在作者机器上能跑**（藏了一堆隐式环境假设）。做自动化的心态要从"能跑一次"切换到"无人值守也可信"。

## 框架（重心：执行健壮性 + 验证幂等/干净环境）

- **框定** — 明确要消灭的**重复劳动**（toil）、触发方式（手动/定时/事件）、期望产物、以及**失败时该怎样**（告警？重试？回滚？）。
  - · 判据：说得清"成功产出什么、失败如何被发现"。
- **勘察** — 摸清手工流程的**每一步**、输入输出、依赖、以及边界情况（空输入、部分失败后重跑、并发运行、数据已存在）。
  - · 判据：能把手工流程完整写成一份步骤清单。
- **谋划** — 设计接口（参数/输入/输出/退出码）；决定**幂等策略**（如何识别"已做过"）、失败处理、日志与可观测。
- **执行** — 先跑通 happy path，再加健壮性：幂等、重试、输入校验、清晰的退出码与日志、危险操作的 dry-run。
- **验证** — **重复运行结果一致**（幂等）；失败时**明确报错而非静默**；在**干净环境**（新容器 / CI）验证，不依赖作者机器的隐式状态。
  - · 判据：连跑两次安全、注入失败会吵、干净环境能从零跑起来。
- **收尾** — 用法文档 + 示例；配置与密钥外置；无魔法值，便于维护。

## 关键手法

- **幂等设计**：让脚本"可安全重跑"——用日期/ID/状态标记识别"这条已处理过就跳过"，部分失败后重跑能续上而非重复或报错。这是自动化最重要的性质。
- **防并发重叠**：定时任务要考虑"上一轮还没跑完、下一轮又启动"——加锁/单实例/检测到在跑就跳过；两个实例同时写同一目标是经典事故。
- **fail loud（失败要吵）**：宁可红着停、发告警，也不要绿着产出脏数据；每一步都检查返回，出错即以**非零退出码**退出并打清晰错误。
- **dry-run / 预览模式**：涉及删除/覆盖/发送的操作，提供 `--dry-run` 先打印"将要做什么"，让人过目再真做。
- **退出码规范**：0=成功，非 0 各表其义，好让上游流水线/调度器据此判断与告警。
- **可定位的日志**：出错时能从日志看出"卡在哪一步、输入是什么、为什么"，而不是只有一句 traceback。
- **配置与密钥外置**：路径、密钥、开关走环境变量/配置文件，别硬编码——否则换环境就废。
- **干净环境验证**：在新容器 / CI 里从零跑一遍，逼出所有"只有我机器上才有"的隐式依赖。

## 反模式（含识别信号）

- ❌ 非幂等、重跑就重复/报错 — _信号：脚本只能"干净地跑一次"，重跑会插重复数据或崩_ → ✅ 设计成可安全重跑
- ❌ 静默吞错、绿着产出脏数据 — _信号：某步失败了脚本还继续、还退出 0_ → ✅ fail loud + 非零退出码
- ❌ 只在本机能跑 — _信号：写死了 `/Users/me/...`、依赖本机装的某工具_ → ✅ 干净环境验证 + 外置配置
- ❌ 危险操作无预览直接执行 — _信号：一跑就批量删除/覆盖，没有 dry-run_ → ✅ 提供 --dry-run
- ❌ 硬编码密钥/路径/魔法值 — _信号：token、绝对路径散落在代码里_ → ✅ 外置配置

## 走一遍（示例）

> 需求：每天凌晨把前一天的日志打包归档到对象存储，并删除本地已归档文件；失败要能发现。
> **框定**：消灭"手工打包上传"这件 toil；定时触发；产物=对象存储里按日期的归档；失败=发告警且不删本地。
> **勘察**：手工步骤=选出昨天的日志→tar 打包→上传→校验上传成功→删本地。边界：某天没有日志、上传中断后重跑、脚本被跑了两次。
> **谋划**：幂等键=归档日期——若对象存储已存在当天归档则跳过上传；**先确认上传成功再删本地**（顺序即安全）；提供 `--dry-run`。
> **执行**：先打通 happy path（打包→上传→删）；再加幂等（已存在则跳过）、上传校验（比对大小/哈希）、失败即非零退出并告警、危险的删除加 dry-run。
> **验证**：同一天连跑两次——第二次识别到已归档、跳过、不重复删（幂等）；模拟上传失败 → 脚本非零退出、发告警、**本地文件仍在**；在干净容器里配好环境变量从零跑通。
> **收尾**：README 写清参数、定时配置、所需权限与环境变量；密钥走环境变量。

## 完成的定义

- [ ] 幂等：连续重跑安全、结果一致（或明确跳过已完成项）；并发重叠有防护
- [ ] 失败明确可诊断（非零退出码 + 定位所需日志），绝不静默
- [ ] 在干净环境（新容器/CI）验证可从零跑起，无隐式本机依赖
- [ ] 危险操作有 dry-run；配置与密钥外置，无硬编码
- [ ] 有用法文档与示例
