# 代码库/系统理解（comprehension）

> **何时在这里**：需要搞懂一个**已存在**的代码库或系统——"这块怎么工作""X 在哪实现""为什么这样设计"，可能是为了接下来改它、答疑、或评估。
> 区分线：外部世界、要查资料 → `research.md`；对着数据找规律 → `data-analysis.md`；目标是评判好坏 → `review.md`。

## 崩点

**目标是建立一个正确、可验证的心智模型，而不是读完所有代码。** 最大的陷阱是**"以为读懂了"**——基于命名、注释和直觉脑补出一个自洽的故事，却从没**追踪真实的执行**去验证它。命名会骗人（`getUser` 可能顺手改了状态），注释会过时，抽象名会误导。只有代码的真实运行是**地面真相**。第二个陷阱是**广度失控**：想把整个库读完，结果淹没在与问题无关的细节里。

## 框架（重心：勘察追踪 + 验证证据）

- **框定** — 明确要回答的**具体问题**，以及"理解到什么程度算够"。是要改一处 bug（需局部深入）还是评估架构（需全局广度）？
  - · 判据：能把目标写成一个可回答的具体问题，而非"看看这个项目"。
- **勘察** — 从**入口/边界**切入（main、路由、API handler、CLI 入口、构建配置、测试），沿一条**真实用例的数据流**逐层追踪调用链，不猜。
  - 先建**粗地图**（有哪些模块、怎么分层、数据往哪流），再对目标区域钻深——先广后深。
  - · 判据：能画出目标用例"从入口到出口"经过了哪些关键环节。
- **谋划** — 决定追踪路径：**跟着一条具体的真实用例走到底**，通常比广撒网读一堆文件高效得多。选那条最能回答你问题的用例。
- **执行** — 逐层追踪，边读边记：画数据流 / 依赖 / 关键抽象 / 状态在哪被改；读**测试**理解模块的意图与契约。
- **验证** — 用**可证伪**的方式检验模型：加日志、跑一遍、构造反例、看真实变量值。**任何结论都要有代码路径或运行证据支撑**，不能只是"看起来像"。
  - · 判据：关键论断都能指到具体代码行，或一次真实运行的观察。
- **收尾** — 用简洁心智模型（一张图 / 几句话）表达；**明确标注不确定与未验证之处**。

## 关键手法

- **跟一条真实请求走全程**：选一个具体输入（一次登录、一笔下单），从入口顺着调用链走到底——一个用例的端到端路径，胜过泛读十个文件。
- **grep 反查入口**：从报错信息、路由字符串、关键函数名、配置项反向搜索，快速定位"这事在哪儿发生"。
- **以代码为准，测试次之，文档再次**：测试反映真实契约与用法示例，文档常年久失修——冲突时信代码。
- **git log / blame 看演化**："为什么这样写"的答案常在历史里——某行 blame 到的提交信息/关联 issue 往往解释了怪异设计。
- **运行它、加断点、打印**：让代码自己告诉你真实的值与流向，而不是你替它想象；对动态语言尤其重要。
- **画出来**：把追踪到的数据流/依赖/状态变化画成简图——画不出来，说明还没真懂。

## 反模式（含识别信号）

- ❌ 靠命名/注释/直觉脑补行为 — _信号：你在说"这个函数应该是做 X 的"却没点开看_ → ✅ 追踪真实调用与运行
- ❌ 想把整个库读完 — _信号：你在逐文件通读、和问题无关的也读_ → ✅ 按具体问题定向、跟真实用例
- ❌ 给出无证据的论断 — _信号：结论是"这里应该是…"而非"这里在第 N 行做了…"_ → ✅ 每个论断指到代码/运行证据
- ❌ 只静态读、不运行 — _信号：面对动态/反射/回调绕晕了还在纯读_ → ✅ 跑一遍、看真实值让代码自证
- ❌ 把不确定说成确定 — _信号：你对没验证的部分也用肯定语气_ → ✅ 显式标注存疑处

## 走一遍（示例）

> 问题："用户偶尔登录后立刻又被登出，鉴权是怎么运作的、问题可能在哪？"
> **框定**：具体问题=登录态的建立与校验流程 + 何处可能导致会话失效；够用的程度=能定位到可疑环节。
> **勘察**：grep 路由找到 `/login` handler 作入口；先建粗地图——登录签发 token、后续请求经一个鉴权中间件校验。跟一条真实登录请求的数据流走。
> **谋划**：选"登录 → 下一次带 token 的请求"这条用例追到底，最能回答问题。
> **执行**：逐层读——登录签发 JWT 写入 cookie；中间件每次校验签名+过期；发现有一段"滑动续期"逻辑会重签 token。读该模块的测试确认其意图。
> **验证**：不臆断，加日志打印每次请求拿到的 token 与校验结果，本地跑一遍 → 观察到续期时新旧 token 短暂并存、旧 token 被判失效 → 印证怀疑（竞态导致偶发登出）。结论有运行证据。
> **收尾**：画出"签发→校验→滑动续期"的流程图，标注"续期竞态"为可疑点与不确定处，交给 debugging play 深挖。

## 完成的定义

- [ ] 框定的具体问题有了明确答案
- [ ] 答案由具体代码路径或真实运行证据支撑（非猜测）
- [ ] 心智模型可用一张图或几句话清楚表达
- [ ] 不确定 / 未验证之处已显式标注
