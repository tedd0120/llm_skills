# 迁移升级（migration）

> **何时在这里**：把系统从 A 搬到 B——换框架、升大版本、迁数据库、搬平台/云、替换核心库。
> 区分线：小版本无破坏升级更接近 `ops.md`；只是内部结构调整、不涉及"新旧并存" → `refactoring.md`。

## 崩点

**大爆炸式一次性切换 = 把所有风险堆在一个不可逆的时刻引爆。** 迁移的两个本质风险是**不可逆性**和**覆盖不全**：切过去才发现漏了一个调用点、回不去、数据对不上。解药永远是三件套：**增量、可回滚、可并行验证**。凡是"关灯换引擎再开灯祈祷"的迁移，都在赌。

## 框架（重心：勘察清点 + 谋划增量 + 验证并行）

- **框定** — 明确源→目标、范围、成功判据、**回滚条件**；评估**爆炸半径**与哪些步骤**不可逆**。
  - 关键问题：能不能新旧并存一段时间？数据是否要迁移/双写？出什么情况就回滚？
  - · 判据：说得清"迁到什么程度算成功""出什么情况就回滚"。
- **勘察** — **穷尽清点**所有受影响项：依赖、调用点、数据、配置、隐式契约、下游消费者。建**兼容性映射**（旧→新逐项对应），标出**破坏性变更**。
  - 怎么清点：全局搜索旧 API/旧库的所有引用；别漏动态调用、配置里的引用、文档/脚本里的调用。静态搜不到的用**运行时观测**兜底：访问日志、埋点、给旧入口加弃用警告，跑一段时间抓漏网调用。
  - · 判据：有一份"受影响项"清单，且你相信它是**全**的。
- **谋划** — 设计**增量切换路径**：绞杀者（strangler fig）/ 双写 / 影子流量 / 特性开关。每步**可回滚**；先迁可逆、低风险、小流量的部分。
- **执行** — 分批切换，全程保留回滚开关；灰度放量，一档一观察。
- **验证** — **新旧并行运行、对比输出**（parallel run / diff）；关键路径逐一验证；**数据一致性校验**。
  - · 判据：新旧行为/数据在样本上逐点一致，差异都能解释。
- **收尾** — 清理旧路径与兼容垫片；更新文档；确认不再有双跑成本。

## 关键手法

- **绞杀者模式（strangler fig）**：在旧系统外围加一层路由，把功能**一块一块**导向新实现，旧的逐步萎缩——而不是一次替换整体。
- **双写 + 校验再切读**：写操作同时打到新旧两边，后台比对一致性；确认稳定后，再把**读**流量从旧切到新。
- **影子流量（shadow）**：把真实流量复制一份打到新系统但不采用其结果，只用来和旧结果对比，零风险验证。
- **特性开关灰度**：1% → 10% → 100%，每档观察指标，随时可一键切回。
- **自动化 diff**：写脚本比对新旧的输出/数据行，别靠人眼抽查——大规模差异只有机器能兜住。
- **先备份、先演练回滚**：回滚路径要真正跑通一次，不能只是"理论上能回"；数据迁移前先快照，给自己一个确定的回退锚点。

## 反模式（含识别信号）

- ❌ 大爆炸一次性切换 — _信号：计划里只有一个"切换日"、没有并存期_ → ✅ 增量绞杀 + 灰度
- ❌ 没有回滚预案 — _信号：你答不出"切了发现不对怎么退回"_ → ✅ 每步可回滚，且回滚路径已演练
- ❌ 漏清点某类调用点/数据 — _信号：你凭印象说"就这几处用到"_ → ✅ 全局搜索穷尽 inventory
- ❌ 切完只做冒烟就宣布成功 — _信号：只点了首页能开就收工_ → ✅ 新旧并行对比 + 数据校验
- ❌ 迁完不清理、长期双跑 — _信号：双写/影子逻辑留在代码里没人敢删_ → ✅ 收尾拆除旧路径与垫片

## 走一遍（示例）

> 目标：用户数据从 MySQL 迁到 PostgreSQL，服务不能停。
> **框定**：成功=所有读写走 PG 且数据一致、可回滚；不可逆点=停写 MySQL 之后。
> **勘察**：全局搜所有读写 user 表的调用点，列全（含一个被定时任务用到的、差点漏掉的）；建字段类型映射，标出 MySQL 与 PG 不兼容的类型（如枚举、时间精度）。
> **谋划**：分五步——(1) PG 建表+历史数据导入，(2) 双写 MySQL+PG，(3) 后台校验两边逐行一致，(4) 读流量灰度切 PG，(5) 停写 MySQL、清理。每步可停可回滚。
> **执行**：先双写、跑校验脚本几天，发现时间精度差异 → 修映射，直到 diff 为零；再把读按 1%→100% 灰度切 PG，盯错误率与一致性。
> **验证**：校验脚本对全量数据 diff 为零；灰度期间新旧读结果一致；关键路径（注册/登录/改资料）逐一手测。
> **收尾**：观察稳定一周后停写 MySQL、删除双写与校验代码、更新文档；MySQL 保留只读快照一段时间做最终回退锚点。

## 完成的定义

- [ ] 全部受影响项已清点并逐一迁移、验证
- [ ] 新旧行为与数据在验证样本上一致，差异都可解释
- [ ] 回滚路径已实际演练、确认可用
- [ ] 灰度/分批完成，无遗留的临时双写/影子逻辑
- [ ] 旧路径已清理或有明确的清理计划与时间点
