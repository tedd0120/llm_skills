# 集成对接（integration）

> **何时在这里**：把你的系统和**别人的系统**连起来——调第三方 API、对接支付/短信/OAuth、打通服务 A 与 B、消费一个外部数据源。
> 区分线：纯自己代码内新增功能 → `implementation.md`；把重复流程自动化 → `automation.md`。

## 崩点

**失败几乎总发生在边界，而不是中间。** 认证、限流、超时、重试、错误语义、数据格式、分页、时区——这些边界条件才是对接翻车的地方。而且**别信文档、信真实响应**：文档常年久失修、含糊、或对错误情况只字不提。只测 happy path 的对接，上线就是定时炸弹——外部系统一定会超时、会限流、会返回你没见过的错误码。

## 框架（重心：勘察真实契约 + 验证失败模式）

- **框定** — 明确要接什么、数据与控制流方向、**成功长什么样、失败长什么样**。
  - 关键问题：调用是同步还是异步？幂等吗？失败能重试吗？有速率限制吗？凭证怎么来？
  - · 判据：说得清"正常一次调用"和"各种失败"分别期望怎样。
- **勘察** — 读两侧**契约**（API / schema / auth 方式）；**用真实调用探明实际行为**（curl / 脚本 / 沙箱）——**地面真相**优先于文档；识别**失败模式**（限流、超时、错误码、分页、幂等要求、字段可空性）。
  - · 判据：你**亲眼见过**真实的成功响应，以及至少一种真实的失败响应。
- **谋划** — 设计最小打通路径 + **错误/重试/超时/幂等**策略；把外部依赖封进**适配层**（业务代码不直接依赖第三方 SDK，便于替换与测试）。
- **执行** — 打**曳光弹**：先打通最薄的一条端到端真实调用，再补健壮性（超时、带抖动的指数退避重试、降级、熔断）。
- **验证** — 在真实/沙箱环境端到端测；**主动注入失败**（断网、超时、返回错误码、限流）验证降级；测边界数据与分页。
  - · 判据：失败注入下系统表现符合预期（正确重试/降级/报错），而非崩溃或静默错误。
- **收尾** — 凭证/密钥**安全管理**（不硬编码、不进日志）；对契约变更加监控；把对接点与已知坑文档化。

## 关键手法

- **先手动探活**：写代码前，用 curl / Postman / 一段脚本打真实接口，看真实 JSON 结构、真实错误、真实限流头——文档说的和它实际返回的经常不一样。
- **适配层封装**：所有外部调用收到一处 `XxxClient`，业务只依赖你的接口；这样能 mock 测试、能换供应商、能集中加重试与日志。
- **超时 + 退避重试 + 幂等 三件套**：网络必然抖动，三者缺一不可——但**只对幂等操作自动重试**（重试非幂等的"扣款/下单"会重复副作用，要靠幂等键）。
- **显式处理限流与分页**：读文档里的 rate limit 与 pagination；遇 429 按 Retry-After 退避；分页要循环取尽，别假设一次拿全。
- **被回调（webhook）也是对接**：验签、防重放、**幂等消费**（对方一定会重发同一事件）、先快速应答再异步处理慢逻辑。
- **不要吞异常**：外部失败要么处理、要么上抛并带上下文；`catch` 后什么都不做是最难查的 bug。
- **沙箱/录制回放测试**：用供应商沙箱或把一次真实响应录下来回放，避免测试依赖真实第三方的可用性与配额。

## 反模式（含识别信号）

- ❌ 信文档不信真实响应 — _信号：你照着文档写完却从没真打过一次接口_ → ✅ 先探活看真实数据
- ❌ 只测 happy path — _信号：你只验证了"正常返回"这一条_ → ✅ 主动注入超时/错误码/限流
- ❌ 硬编码密钥、密钥进日志 — _信号：token 直接写在代码里或被打进日志_ → ✅ 安全管理凭证
- ❌ 无超时/无重试的裸调用 — _信号：一个直接的同步调用，没设超时_ → ✅ 超时+退避重试+幂等
- ❌ 自动重试非幂等操作 — _信号：对"下单/扣款"配了盲目重试_ → ✅ 用幂等键，或不自动重试

## 走一遍（示例）

> 需求：接第三方短信服务，发送登录验证码。
> **框定**：成功=对方返回受理成功、用户收到；失败=余额不足/号码非法/限流/超时，各要有明确处理；发送是非幂等的（重发=多一条短信+多花钱）。
> **勘察**：先 curl 沙箱真实发一条 → 看到成功响应结构，也故意发非法号码看错误码；读文档发现每号每分钟限 1 条（会返回 429）。
> **谋划**：封 `SmsClient` 适配层；设 5s 超时；**不盲目重试**（非幂等），失败按错误码分类返回；限流命中则告知用户"稍后再试"。
> **执行**：先打通一条真实发送（曳光弹），再补：超时处理、429 映射为"请求过频"、非法号码映射为"号码有误"。
> **验证**：注入超时（断网）→ 返回"发送失败请重试"不卡死；连发触发 429 → 正确提示；非法号码 → 正确提示。真机收到验证码。
> **收尾**：密钥放环境变量、不进日志；对"发送失败率"加监控告警；文档记下限流规则与错误码映射。
