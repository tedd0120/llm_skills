# 规划设计（planning）

> **何时在这里**：产物本身是一份**计划或设计**——系统架构、技术方案、实施路线图、项目计划。宏观任务往往从这里起步。
> 区分线：计划要**落地执行且跨多步** → 交给 `orchestration.md` 统筹；要在既定方案里选一个 → `decision.md`；单个功能的局部设计 → 直接在 `implementation.md` 的框定/谋划里做即可。

## 崩点

**计划的价值在于让真实的约束和风险提前暴露，而不是画一张漂亮的蓝图。** 头号失败是**脱离现实**——计划在纸上完美，一碰真实系统就碎；以及**忽略未知、假装一切确定**。好计划的标志恰恰是**显式标出不确定性**并优先去消除它：把"最可能推翻整个方案的假设"排到最前先验证，而不是留到最后爆雷。

## 框架（重心：勘察地形 + 验证压测）

- **框定** — 澄清**真实目标、约束、成功判据、非目标**；利害与时限。
  - 关键问题：这要解决谁的什么问题？硬约束（技术/时间/合规/团队能力）是什么？什么明确不做？
  - · 判据：说得清"做成什么样算成功、什么明确不做"。
- **勘察** — 摸清**现状/地形**：既有系统、限制、依赖、干系人；**找出未知与假设**。
  - · 判据：列得出关键约束，和"我还不知道 / 在假设"的事项。
- **谋划** — 探索**多个方案并权衡**（别只有一条道）；选型；分解为**里程碑与可交付**；排序时**先降风险、先验证核心假设**。
- **执行** — 写出结构化计划：目标 · 方案与取舍 · 分解 · 顺序/里程碑 · **风险与缓解** · **未知与验证方式** · 完成的定义。
- **验证** — **压测计划**：最大的风险是什么？哪些是没验证的假设？失败会怎样？请人或自己**反驳（grill）**一遍。
  - · 判据：每个关键假设都配了"如何验证 / 如果错了怎么办"。
- **收尾** — 计划可执行、可度量、可调整；标出**决策点**与**回退点**。

## 关键手法

- **至少两个方案对比**：只有一个方案，说明你还没在思考、而是在为既定选择辩护；对比逼出取舍。
- **先降风险（de-risk first）**：把"最可能推翻方案的假设"排到最前，用一个最小实验/原型去验证它，别把它压到最后。
- **显式列"待验证假设"**：把不确定摆到明面（"假设峰值并发 < 1000，待压测确认"），而不是藏进乐观估计里。
- **里程碑可交付、可验证**：每个里程碑结束时"能拿出什么、怎么确认它成了"——避免"进行中"永远说不清进度。
- **识别关键路径与依赖**：哪些必须串行、哪些能并行、卡住哪个会阻塞全局——这决定排期与风险。
- **预留回退点**：在不可逆/高成本的步骤前，设计一个能退回的检查点，别让计划变成没有刹车的单行道。
- **区分可逆与不可逆决策**：不可逆的多想、早定；可逆的别过度规划，留给执行期试。

## 反模式（含识别信号）

- ❌ 单方案一条道 — _信号：你的方案里只有一个选择、没有备选与取舍_ → ✅ 多方案权衡
- ❌ 忽略未知、假装全确定 — _信号：通篇没有"假设/待确认/风险"字样_ → ✅ 显式列假设并优先验证
- ❌ 计划无验收/无度量 — _信号：里程碑说不清"怎么算完成"_ → ✅ 每里程碑配完成的定义
- ❌ 纸上完美、脱离真实地形 — _信号：计划没提任何现有系统的约束_ → ✅ 基于勘察到的现状
- ❌ 把不可逆决策塞进"以后再说" — _信号：关键的单向门决策被含糊带过_ → ✅ 提前识别、慎重对待

## 走一遍（示例）

> 任务：设计一个"站内实时通知"系统方案。
> **框定**：目标=用户能及时收到站内通知；约束=用现有技术栈、两人两周；非目标=不做邮件/短信/App 推送。成功判据=通知延迟秒级、不丢。
> **勘察**：地形——已有消息队列、Web 前端；未知=峰值并发通知量、是否必须"实时"到秒。列为待验证假设。
> **谋划**：三方案权衡——(A) 前端轮询：简单、但延迟与负载差；(B) WebSocket 长连接：实时、但要处理连接管理与扩容；(C) 第三方推送服务：快、但引入外部依赖与成本。分解里程碑：M1 通知存储与已读态、M2 推送通道、M3 前端接入。先做能降风险的：M0 快速压测"峰值并发假设"。
> **执行**：写出计划文档，含三方案取舍、推荐（B，理由匹配约束）、里程碑、风险表（连接扩容、消息丢失）、待验证假设（并发量）、每步 DoD。
> **验证**：自我 grill——最大风险是"并发量超预期导致长连接扛不住"→ 缓解=M0 先压测，若超阈值则退化到方案 C；"消息会不会丢"→ 用队列 + 已读态补偿。每个假设都有验证与退路。
> **收尾**：标出决策点（M0 压测结果决定 B 还是 C）与回退点；计划随压测结果可调。

## 完成的定义

- [ ] 目标、约束、成功判据、非目标明确
- [ ] ≥2 个方案经过权衡，选型有据
- [ ] 分解为可交付、可验证的里程碑，依赖与关键路径清晰
- [ ] 风险与**未验证假设**已显式列出，各配验证/缓解方式
- [ ] 关键决策标注了可逆性，并预留了回退点
