# 重构（refactoring）

> **何时在这里**：改善代码的**内部结构**——可读性、去重、解耦、命名——而**对外行为完全不变**。
> 区分线：只要行为会变（修 bug、加功能、改性能特征），就不是重构，分别去 `debugging.md` / `implementation.md` / `performance.md`。把它们和重构**混在一次提交里**是经典错误。

## 崩点

**"行为不变"是硬约束，也是唯一真正的敌人。** 危险不在于改得好不好看，而在于**重构过程中悄悄改变了行为却浑然不觉**。没有测试网托底的重构，是在走钢丝——每一步都可能无声地摔下去而你听不到响。所以重构的第一动作永远是"先确认我有一张能感知行为变化的网"。

## 框架（重心：勘察建网 + 执行小步等价）

- **框定** — 明确**为什么改**（可读性？为下一步功能铺路？消除重复？）与**爆炸半径**（这块被多少地方依赖）。把"行为不变"钉成硬约束。
  - · 判据：说得清"改完什么变了（结构）、什么绝不能变（行为）"。
- **勘察** — 用测试**钉住当前行为**。覆盖不足？先补一层**特征测试**（characterization test：不评判对错，先把现状锁下来）。
  - 怎么补：对目标函数喂一组代表性输入，把当前输出直接断言为期望——哪怕当前输出其实是"错"的，也先锁住，重构阶段不改它。
  - · 判据：改动区域有能感知行为变化的测试，且当前全绿。
- **谋划** — 把大改拆成**一串小的、可逆的、每步都能验证等价**的变换（改名 / 抽取 / 内联 / 搬移 / 引入参数对象，各自独立）。排出顺序，先做最安全的。
- **执行** — **一次一个小变换**，每步之后立即跑测试保持常绿；像**曳光弹**一样小步推进，任何时刻都能停下来交付。
- **验证** — 全测试绿，且断言语义未被悄悄放宽；对外行为逐点等价；无功能/bug 修复混入。
  - · 判据：diff 里只有结构变化，没有可观察行为的变化。
- **收尾** — 提交粒度小、信息清晰，**一次提交只做一种变换类型**（改名一个提交、搬移一个提交）。

## 关键手法

- **特征测试（characterization test）**：给遗留代码"拍快照"——把它当前的实际输出固化为断言，为无测试的代码临时织一张网，重构完再考虑是否修正那些"锁住的错误"。
- **IDE 自动重构优先**：改名、抽取方法/变量、内联、移动——让工具做机械变换，比手改安全得多（它保证引用同步更新）。
- **一种变换一次提交**：把"抽取函数"和"重命名"分到两个提交，diff 才可读、可单独回滚、可单独审。
- **保持常绿（green-to-green）**：每个小变换前后测试都必须绿；绝不允许出现"改了一半、红着"的中间状态跨越多步。
- **diff 自检**：审自己的 diff，逐处问"这行改变可观察行为了吗？"——只要"可能会"，退回去加测试再动。
- **克制范围**：重构最易失控成"顺便把这也改了"。记住 YAGNI，只做当前目标所需的结构变化。

## 反模式（含识别信号）

- ❌ 无测试就大刀阔斧 — _信号：你在改一段"没有任何测试覆盖"的代码_ → ✅ 先补特征测试再动
- ❌ 重构夹带修 bug/加功能 — _信号：diff 里既有搬移又有新逻辑/行为修正_ → ✅ 拆开，行为改动另走 play、另开提交
- ❌ 一口气改完再统一测 — _信号：你连着做了 5 个变换才第一次跑测试_ → ✅ 每个变换后就跑
- ❌ 悄悄放宽了断言/边界 — _信号：为了让测试通过，你改动了断言而非代码_ → ✅ 断言语义必须原样保留
- ❌ 把"重写"当重构 — _信号：你在大段删除重写，而非等价变换_ → ✅ 那是新建，走 implementation + migration 思路

## 走一遍（示例）

> 目标：三个 handler 里各有一段几乎相同的"校验请求参数"逻辑，想抽成一个函数。
> **框定**：目标=去重、行为不变；爆炸半径=这三个 handler。
> **勘察**：这三段目前无直接测试 → 先各补一条特征测试：喂合法/非法参数，把当前的返回码与错误信息锁成断言，跑绿。
> **谋划**：拆成 (1) 抽取第一处为 `validateParams`，(2) 第二处替换调用，(3) 第三处替换调用，(4) 统一细微差异。每步独立。
> **执行**：用 IDE"抽取方法"做 (1)，跑测试→绿；(2)(3) 逐个把重复段替换成调用，每次跑测试→绿；(4) 处理三处原本的细微不一致时发现其中一处校验其实漏了一个字段——**打住**：这是行为变化，记下来另开 issue/提交，本次重构保持三处原样等价。
> **验证**：四条特征测试全程绿，diff 只有"抽取+替换调用"，无行为变化。
> **收尾**：四个小提交，信息分别写清；那处"漏校验"另起一个 fix 提交（走 debugging）。

## 完成的定义

- [ ] 相关测试全绿，且没有任何断言语义被削弱
- [ ] 对外可观察行为逐点不变
- [ ] 每一步变换都可独立回滚
- [ ] 未混入任何功能改动或 bug 修复
- [ ] 提交粒度小、每个提交只做一类变换、信息清晰
