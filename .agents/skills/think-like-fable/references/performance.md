# 性能优化（performance）

> **何时在这里**：某个东西**能跑但不够快 / 太耗资源 / 太贵**——延迟、吞吐、内存、CPU、成本。
> 区分线：结果不对 → `debugging.md`；要新增能力 → `implementation.md`；只是代码难看 → `refactoring.md`。

## 崩点

**没测量就优化 = 蒙眼开枪。** 程序把绝大部分时间花在你**猜不到**的地方——真实瓶颈几乎总在意料之外。第二杀手是**过早优化**：为一个非瓶颈牺牲可读性与正确性，徒增复杂度债却毫无收益。铁律：先测量 → 锁定主瓶颈 → 只打那一个 → 复测确认。没有"前/后同口径的数字"，就等于什么都没证明。

## 框架（重心：勘察测量 + 验证复测）

- **框定** — 定下**量化目标**：p95 延迟 < X ms？吞吐 > Y？内存 < Z？成本降多少？没有数字目标就先和用户定一个——这就是**完成的定义**。
  - 关键问题：优化的是延迟还是吞吐？在什么负载下？可接受的正确性/可读性代价是多少？
  - · 判据：有明确、可测的指标与阈值。
- **勘察** — 用 profiler / 基准 / 真实负载**测量当前状态**，定位**主瓶颈**（80/20：极少数热点通常吃掉绝大部分开销）。
  - 建立一个**可复现的基准**（固定输入、固定环境、多次取中位数）——它同时是你之后验证的量尺。
  - · 判据：有数据明确指出"时间/资源花在哪一段"，而非猜测。
- **谋划** — 针对**主瓶颈**选优化，按杠杆从高到低排：**消除不必要的工作（这活能不能不干/少干）> 降低复杂度阶数 > 缓存/批处理 > 并行 > 微优化**。优先高收益、低风险、低复杂度的。
- **执行** — 一次一个优化，保持功能正确；改完立即回到基准。
- **验证** — 用**同一基准**复测，量化前后提升；确认无正确性回归；确认瓶颈是被**解决**而非被**搬**到别处。
  - · 判据：有前/后对比数字，达到框定阈值，且功能结果一致。
- **收尾** — 记录基准数字（前/后）与优化理由，**基准脚本保留可复跑**（防未来性能悄悄回归）；评估引入的复杂度是否值得，别留下没人敢碰的"黑魔法"。

## 关键手法

- **profiler 定位**：CPU profiler 看热点函数/火焰图，找占时最高的调用；别靠"感觉这里慢"。先测再动是纪律。
- **识别经典真凶**：N+1 查询、缺索引、循环内 I/O / 循环内查询、无谓的序列化/深拷贝、重复计算无缓存、同步阻塞该并发的地方、网络往返过多。
- **盯复杂度阶数**：O(n²)→O(n log n) 的算法改进，随数据规模拉大，收益碾压任何常数级微优化。
- **缓存**：对"重复计算且结果稳定"的最有效——但**必须配失效策略**，缓存是最容易引入正确性 bug 的优化。
- **批处理 / 合并往返**：把 N 次小请求/查询合成 1 次批量，常是最高性价比的一招。
- **测真实负载**：用接近生产的数据规模与分布；玩具输入会把瓶颈藏起来，微基准会被 JIT 预热/缓存局部性骗。
- **端到端计时**：先量整条链路各段耗时占比，再决定打哪段——别一头扎进某个函数。

## 反模式（含识别信号）

- ❌ 凭直觉优化 — _信号：你还没跑 profiler/基准就开始改代码_ → ✅ 先测量定位
- ❌ 优化了非瓶颈 — _信号：你在抠一个只占 2% 耗时的函数_ → ✅ 回到 80/20，打主瓶颈
- ❌ 为微小提升牺牲正确性/可读性 — _信号：代码变得没人看得懂，只快了一点点_ → ✅ 权衡收益与复杂度债
- ❌ 只测一次、无对照 — _信号：你说"快多了"但拿不出前后数字_ → ✅ 前后同基准量化
- ❌ 把瓶颈搬到别处还以为解决了 — _信号：这段快了，但整体端到端没变快_ → ✅ 复测端到端

## 走一遍（示例）

> 现象：订单列表接口 p95 800ms，目标降到 200ms 内。
> **框定**：指标=p95 延迟 <200ms，负载=每页 50 条订单，正确性不可退。
> **勘察**：建基准（固定 1000 次请求取 p95）；上 profiler → 90% 时间在一个循环里，对每条订单单独查一次用户名（N+1，50 次 DB 往返）。
> **谋划**：主瓶颈明确是 N+1。方案：一次性批量查这 50 个 user_id 的用户名，内存里 join。杠杆高、风险低。
> **执行**：把循环内单查改为循环前一次 `WHERE id IN (...)` 批量查 + 建 map；循环里查 map。
> **验证**：同基准复测，p95 降到 150ms，达标；比对新旧返回体逐条一致（无正确性回归）；确认没把耗时挪到别处。
> **收尾**：记录"800ms→150ms，根因 N+1"；顺手确认列表页其他接口有无同样 N+1（发现一处，另开优化）。

## 完成的定义

- [ ] 有量化的前/后数字，且达到框定阈值
- [ ] 优化基于测量定位的真实瓶颈（非猜测）
- [ ] 功能正确性无回归（含边界与缓存失效）
- [ ] 瓶颈被解决而非转移到别处（端到端复测确认）
- [ ] 引入的复杂度有据可依并已记录
