# 测试验证（testing）

> **何时在这里**：要为某段行为**建立信心**——写测试、验证一个改动是否真的对、确认没有回归。
> 区分线：这是"造安全网"的活。若在查一个已知故障 → `debugging.md`（但修完要回这里补回归测试）；若在评判别人的测试够不够 → `review.md`。
> 注意：「验证」（每个 play 共有的第五阶段）是"对照完成的定义检查这次工作"；本 play 是"专门产出测试资产"这件任务本身。

## 崩点

**测试的唯一价值是能抓住真实的回归。** 两个杀手：**mock 掉了一切**——测试全绿，却没测到任何真实行为，纯粹在验证 mock 自己（改坏真实代码它照样绿）；以及**只测 happy path**——真实世界的 bug 几乎都藏在边界和失败路径里。还有一个隐形杀手：**你从没见过这个测试失败**，于是它可能因为断言写错、根本没跑到，而什么都没在测。

## 框架（重心：谋划用例 + 验证真实行为）

- **框定** — 明确"**正确**"意味着什么、要防住哪些**回归**、覆盖到什么程度算够。
  - · 判据：说得清"什么行为必须永远成立"。
- **勘察** — 理解被测行为的规格与边界；识别**高风险 / 易错点**（复杂分支、边界值、并发、外部依赖、状态迁移）。
  - · 判据：列得出"这段最可能在哪儿出错"。
- **谋划** — 设计**用例集**：happy path + **边界**（空、零、负、极大、超限）+ **失败/异常**（非法输入、依赖报错）+ 对抗性输入；决定测试层级（单元 / 集成 / 端到端）。
- **执行** — 写测试。**先让它因缺陷而失败（红）**，确认它真的在测东西，再让它通过（绿）。
- **验证** — 观察**真实行为**而非假设；确认测试**确实会因回归而变红**（故意改坏代码看它红）；避免脆弱、依赖时序/顺序、虚假通过的测试。
  - · 判据：每个测试都亲眼见过它"该红时红、该绿时绿"。
- **收尾** — 测试**可读、独立、快**；命名表意（一看就知道测什么、什么条件）；纳入 CI 自动运行。

## 关键手法

- **每个测试先看它失败**：断言写好后，先在"未实现/故意改坏"的状态下跑一次看它红——没见过红的测试等于没验证它在测什么。
- **测行为，不测实现**：断言"输入 X 得到输出 Y / 产生副作用 Z"，而非"内部调用了某函数"——后者一重构就假红，却抓不到真 bug。
- **边界与失败优先**：happy path 一条足矣，把预算投到边界（空/零/负/极大/超限）与失败路径——bug 都在这儿。
- **少 mock 关键路径**：mock 掉数据库/网络的"集成测试"往往掩盖真 bug；核心链路要有真实或近真实（内存库、testcontainers、录制回放）的端到端验证。
- **测试独立可重复**：不依赖执行顺序、不共享可变全局状态、不受时钟/时区/随机数影响（注入固定时钟与种子）。
- **一条端到端冒烟**：至少一个把各部分拼起来真跑的用例，证明它们能协作。

## 反模式（含识别信号）

- ❌ 只测 happy path — _信号：你的用例全是"正常输入正常输出"_ → ✅ 覆盖边界 + 失败 + 对抗输入
- ❌ mock 掉一切、测了个寂寞 — _信号：改坏真实逻辑测试还全绿_ → ✅ 关键路径测真实行为
- ❌ 从没见过测试失败 — _信号：你写完直接绿，没在"坏"的状态下跑过_ → ✅ 先红再绿、改坏代码验证它会红
- ❌ 断言内部实现细节 — _信号：断言"调用了 repo.save 一次"这类实现_ → ✅ 断言可观察行为
- ❌ 脆弱测试 — _信号：换个执行顺序/换台机器/到了跨天就挂_ → ✅ 独立、可重复（注入时钟/种子）

## 走一遍（示例）

> 目标：给 `calcDiscount(price, coupon)` 写测试。
> **框定**：正确=按券规则算出应付价，且非法/越界输入不能算出离谱结果（负价、免费、超额折扣）。要防的回归=改券逻辑时别算错钱。
> **勘察**：识别易错点——边界：price=0、coupon 折扣=0%/100%/>100%、券过期、多券叠加、负数 price（脏数据）。
> **谋划**：用例集——happy（8 折得正确价）；边界（0 元、100% 券得 0、>100% 券应被封顶而非负价、过期券不生效）；失败（price 为负/非数 → 抛错或安全值）。单元级即可。
> **执行**：先写"100% 券封顶为 0、不出现负价"的断言，在**还没做封顶逻辑的代码**上跑 → 红（证明它真在测这条规则）；再实现封顶让它绿。
> **验证**：故意把封顶去掉 → 该测试立刻变红（确认它能抓回归）；测的是"最终价格"这一行为，不是内部怎么算的；用固定输入、无时钟依赖，可重复。
> **收尾**：用例命名如 `折扣超过100%时价格封顶为0`；跑得快、互相独立；加入 CI。

## 完成的定义

- [ ] 覆盖 happy path + 边界 + 失败路径
- [ ] 每个测试都见过它"该红时红、该绿时绿"
- [ ] 测的是行为而非实现细节（重构不会误报）
- [ ] 关键链路有真实/近真实的端到端验证，未被 mock 架空
- [ ] 测试独立、可重复、命名表意，已纳入 CI
