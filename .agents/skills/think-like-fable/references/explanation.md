# 讲解教学（explanation）

> **何时在这里**：把一个概念/机制**讲懂给某个人**——回答"这是什么意思""教我 X""为什么会这样"。重点是**理解的转移**，通常是互动的、因人而异的。
> 区分线：产出一份静态文档 → `writing.md`；自己要搞懂（不是教别人）→ `comprehension.md` / `research.md`。

## 崩点

**从对方的已知出发，架一座桥到未知。** 头号失败是**知识的诅咒**（curse of knowledge）：你太熟了，于是用一堆对方并不具备的前提去解释，桥的这头就没搭在他站的地方，越解释越懵。第二杀手是**假检验**——问"你懂了吗"，对方出于礼貌点头，其实没懂，你却以为讲通了。

## 框架（重心：框定听众 + 验证真懂）

- **框定** — 判断**听众水平**与目的：他已经会什么、要理解到什么程度、拿来干嘛（应付考试？做决策？动手用？）。
  - · 判据：说得清"对方的起点在哪、终点要到哪"。
- **勘察** — 找到对方已有的**锚点**（能类比的已知概念）与目标概念之间的**差距**。
  - · 判据：找到了至少一个对方熟悉、可作桥墩的概念。
- **谋划** — 规划**从已知到未知的最短桥**：先给直觉/类比，再上精确定义；先整体图景后细节。
- **执行** — **由浅入深**，具体例子先行；**一次只引入一个新概念**（新术语落地、用过一次，再引下一个）；用类比、但点明类比在哪里失效。
- **验证** — **让对方应用/复述/预测**来检验是否真懂，而不是问"懂了吗"；发现卡点就回退、换个锚点重讲。
  - · 判据：对方能用自己的话复述，或解一道新的应用题。
- **收尾** — 给可自查的要点 + 下一步；为想深入的人留一条更深的路径（分层）。

## 关键手法

- **对抗知识诅咒**：默认对方没有你的背景，从他真正站的地方起步；每用一个术语，先确认它在对方的已知集里，否则先搭它。
- **先动机后机制**：先讲"为什么需要它 / 它解决什么问题"，再讲"它怎么运作"——动机给了细节一个安放的钩子，否则细节无处挂靠。
- **具体先行、再抽象**：先给一个摸得着的例子，再从中归纳出一般规律；人是从例子学会抽象的，反过来很难。
- **一次一个新概念**：每个新术语引入后立刻用一次、落地，再引下一个；同时塞三个新词，对方一个都留不住。
- **类比要标边界**："像水管一样"——但说清哪里像、哪里不像，否则一个好类比会在边界处制造新的误解。
- **真检验**：让对方预测下一步、举个你没给过的新例子、或把它讲回给你——"懂了吗"式点头不算数。

## 反模式（含识别信号）

- ❌ 用对方没有的前提去解释 — _信号：你的解释里塞满对方还没学过的术语_ → ✅ 从其已知锚点出发
- ❌ 一次塞进太多新概念 — _信号：一句话里三个新名词_ → ✅ 逐个引入、各个落地
- ❌ 只讲"怎么做"不讲"为什么" — _信号：你直接上步骤/定义，没说动机_ → ✅ 先动机后机制
- ❌ "你懂了吗"式假检验 — _信号：你靠对方点头判断讲通了_ → ✅ 让对方应用/复述/预测
- ❌ 类比不标边界 — _信号：类比用得很爽但没说它哪里不成立_ → ✅ 点明类比何处失效

## 走一遍（示例）

> 场景：给一位非技术的产品经理讲清"什么是 API"，目的=他能和工程师顺畅沟通需求。
> **框定**：听众=懂业务、不懂技术；终点=能理解"系统之间通过约定的接口要数据"，够他提需求即可，不需讲协议细节。
> **勘察**：找锚点——他熟悉"餐厅点菜"：顾客不进厨房，通过服务员按菜单点单、拿到菜。
> **谋划**：桥=餐厅类比 → 引出"接口是约定好的请求方式" → 再落到"系统 A 通过 API 向系统 B 要数据"。
> **执行**：先动机（"为什么系统之间不直接乱翻对方数据库？因为要安全、要有约定"）→ 类比（服务员=API，菜单=能点的东西/端点，点单=请求，上菜=响应）→ **标边界**（"但和餐厅不同，API 每秒能处理成千上万次点单"）→ 一次只引一个新词。
> **验证**：不问"懂了吗"，而是让他**举个自己产品里的例子**——他说"那我们 App 里显示天气，是不是就是向天气公司的 API 点了一次'今天天气'的单？"——复述正确，真懂了。
> **收尾**：给三句话要点小结；留一条深入路径（"想再懂点可以了解'请求参数'和'返回字段'，就是点菜时的备注和上菜的摆盘"）。

## 完成的定义

- [ ] 从听众真实已知的锚点起步（无未声明的前提）
- [ ] 一次一个新概念，每个都有具体例子落地
- [ ] 已通过应用/复述/预测**真检验**对方理解，而非点头
- [ ] 卡点已被识别并换路径讲通
- [ ] 给了要点小结与可深入的下一步
