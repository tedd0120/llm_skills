# 360Teams 自定义修改

## 选择修改内容

用户已说明目标功能时，直接检查并执行该项修改。
用户只调用 skill 时，先询问想修改的功能，列出系统代理、QWork、AI 灵记，并允许填写其他功能。

| 功能 | 当前操作 | 按需读取 |
|---|---|---|
| 系统代理 | 检查实际代理端口与请求链路，启用或撤销客户端代理修复 | [代理检测](references/proxy.md) |
| QWork | 启用或停用后台运行组件与界面入口 | [功能启停](references/features.md) |
| AI 灵记 | 启用或停用录音、转写、悬浮窗与界面入口 | [功能启停](references/features.md) |
| 其他功能 | 分析当前安装包、依赖和调用方，实施用户指定修改 | 下文“其他功能” |

启停在客户端退出并重新启动后生效。
用户要求修改具体功能时，授权包含该功能补丁的准备、安装和必要的客户端重启。
只读检查或原理咨询以报告结束。

## 实施与验收

1. 从实际进程或安装信息确定客户端与 `app.asar` 路径，读取现有补丁状态。
2. 修改程序包前读取[构建与完整性要求](references/builds.md)。使用当前构建的源文件与调用证据确认适配。
3. 用 `scripts/customize.cjs` 准备候选包，仅指定本次修改的开关。检查候选包完整性、功能组合与备份。
4. 正常退出客户端，确认全部进程退出后应用补丁，再正常启动客户端。
5. 验证目标功能状态、消息页与待办页，并核对已有其他修改仍然生效。界面隐藏与后台停用分别验证。
6. 报告实际修改、验收结果和状态目录。失败安装恢复到本次安装前快照，再核实可启动状态。

日常启用或停用使用对应功能开关。
`restore` 用于撤销最近一次安装。
客户端升级或发生未登记修改后，重新分析并适配构建。

## 其他功能

读取当前交付包，使用可用的 REA 分析入口、调用关系和运行证据。
确认功能涉及的主进程模块、renderer、IPC、原生组件、持久数据和服务端依赖。
选择可独立控制的入口，保留共享模块所需的接口。
将用户指定功能的补丁和恢复方法加入本 skill，并完成对应验收。
需要服务端配合或无法独立关闭时，说明实际边界与可实施范围。

## 文件位置

依赖在 skill 目录执行 `npm ci --ignore-scripts --no-audit --no-fund` 安装，需要 Node.js 22.12+。
代理诊断脚本需要 Windows 与 Python 3.10+。

报告使用 `data/360teams-customization/`。
原包、快照、候选包与功能状态使用 `.local/360teams-customization/<安装标识>/`。
`--output-dir` / `--state-dir` 优先；随后读取 `LLM_SKILLS_DATA_DIR` / `LLM_SKILLS_STATE_DIR`、脚本所属仓库和用户级 `~/.llm-skills/`，与 cwd 无关。
